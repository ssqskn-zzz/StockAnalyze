## 0. 阅读指引

### 0.1 术语（全文统一口径）

| 术语 | 定义 |
|---|---|
| 企业 | 一家被分析的主体，可上市（A 股 / 港股 / 美股）或非上市；以"企业"为工作台的一级容器 |
| 报告期 | 一个财务期间，如"2024 年年度报告""2025 年半年度报告""2025 年第一季度报告" |
| 指标（指标项） | 指标字典中的一个受控条目，如"营业总收入""经营活动现金流量净额"，带固定定义与单位 |
| 指标值 | 某企业在某报告期上的一项指标取值，是最小可追溯、可确认、可版本化的数据单元 |
| 抽取批次 | 用户一次投递（可含多份文件）触发的处理任务集合 |
| 报告版本 | 深度分析报告的一次完整快照，新版本不覆盖旧版本 |
| 估值版本 | DCF 模型的一次参数 + 结果快照 |
| 确认状态 | 指标值的可信状态：机器提取 → 待确认 → 已确认 → 已锁定 |
| 数据血缘 | 指标值来自哪份文件、哪张表、哪一页、由谁在何时修改 |

## 1. 产品定位与目标用户

### 1.1 一句话定位

把"读年报 → 提数据 → 写分析 → 做 DCF"这条原本散落在 Excel、Word 和个人记忆里的工作流，收拢成一个**按企业沉淀、可增量更新、可追溯版本**的价值投资研究工作台。

解析、抽取、写报告、做测算都在**助手侧**完成；工作台只负责承载结果、管理版本、呈现规则与收集人工确认。

### 1.2 目标用户

| 用户 | 特征 | 核心诉求 |
|---|---|---|
| 个人价值投资者（主） | 自建 Excel 模型，长期跟踪 5–30 家企业 | 数据不重复录入、口径一致、换年时能"续写"而不是重写 |
| 小型研究团队（次） | 2–5 人分工覆盖行业 | 同一企业多人维护，结论与数据可追溯到来源与版本 |

### 1.3 使用场景

| 场景 | 触发 | 用户动作 | 完成标志 |
|---|---|---|---|
| S1 首次建企 | 决定研究一家新公司 | 在**助手会话**中投递多年年报/季报 + 指定企业 | 工作台出现该企业，含覆盖报告期、数据表、首版报告 |
| S2 估值测算 | 数据齐备后判断贵不贵 | 在估值页确认/调整假设，由助手测算 | 得到每股内在价值区间与敏感性表，且可回溯所用数据 |
| S3 增量续更 | 新年报/半年报/季报发布 | 在助手会话中补充新文件并指定同一企业 | 新增报告期入表，报告生成新版本（保留旧版），估值提示需复核 |
| S4 新增企业 | 覆盖新标的 | 同 S1，企业为新建 | 企业列表新增一行，与既有企业互不干扰 |

### 1.4 产品不做的事（摘要，详见第 3.3 节）

不做行情看板、不做买卖建议、不做组合与回测、不做自动下单、不对外分发报告原文。

## 2. 产品模型

### 2.1 对象关系

```
企业 Company
 ├── 报告期 Period ──┬── 指标值 MetricValue（每条带来源、置信度、确认状态）
 │                   └── 来源文件 SourceFile（年报 PDF / 季报 / 上传件 / 抓取件）
 ├── 深度报告 Report ── 报告版本 ReportVersion（v1, v2, …，只增不改）
 ├── 估值模型 ValuationModel ── 估值版本 ValuationVersion（参数 + 结果快照）
 └── 抽取批次 IngestionBatch（投递 → 解析 → 校验 → 确认 → 入库）
```

一句话：**指标值是唯一事实源**，报告与估值都是它的下游消费者。任何上游变更都必须能回答"影响了哪一版报告、哪一版估值"。

### 2.2 关键对象定义

| 对象 | 作用 | 关键约束 |
|---|---|---|
| 企业 | 一级容器，聚合所有报告期、报告、估值 | 同一市场内证券代码唯一；无代码企业按"名称 + 成立年份"去重 |
| 报告期 | 时间轴上的锚点 | 唯一键 = 企业 + 期间类型 + 财年 + 期间序号 |
| 指标值 | 最小数据单元 | 每条必须有来源；同一(企业, 报告期, 指标)只有一个"当前有效值" |
| 抽取批次 | 一次投递的处理单元 | 允许部分成功；失败项必须可定位到具体文件与页 |
| 报告版本 | 分析结论的时间切片 | 发布后不可修改，只能出新版本 |
| 估值版本 | 测算结果的时间切片 | 明确记录"基于哪些指标值版本"，数据变动即标记过期 |

### 2.3 状态机

**抽取批次**

| 当前状态 | 可流转到 | 触发 |
|---|---|---|
| 待解析 | 解析中 / 已取消 | 用户确认投递 / 用户撤销 |
| 解析中 | 待校验 / 解析失败（部分失败） | 解析完成 |
| 待校验 | 待确认 / 校验不通过 | 勾稽校验完成 |
| 待确认 | 已入库 / 部分入库 | 用户完成确认 |
| 已入库 | （终态，可被新批次引用） | — |
| 解析失败 / 校验不通过 | 重新解析 / 已取消 | 用户修复后重试 |

**指标值**

| 当前状态 | 可流转到 | 说明 |
|---|---|---|
| 机器提取 | 待确认 | 置信度中/低一律落到待确认 |
| 待确认 | 已确认 / 有争议 | 用户逐项或批量确认；争议项不参与估值 |
| 已确认 | 已锁定 | 被报告发布或估值确认引用后自动锁定 |
| 已锁定 | 已确认（解锁） | 仅当引用它的版本全部归档时可解锁并重算 |

**报告版本 / 估值版本**

| 当前状态 | 可流转到 | 说明 |
|---|---|---|
| 草稿 | 待审阅 | 生成完成 |
| 待审阅 | 已发布 / 退回草稿 | 用户通过 / 要求重生成 |
| 已发布 | 已归档 | 出现更高版本时自动归档 |
| 新任版本 | 已发布 | 旧版本转"已归档"，仍可查看与对比 |

### 2.4 处理位置与职责边界（工作台无模型能力）

工作台是**结果容器与规则界面**，不承担解析、抽取、写作等生成类工作；这些动作全部在**助手侧**完成——用户在助手会话中投递材料、指定企业，助手处理完写入工作台。

| 能力 | 助手侧 | 工作台 |
|---|---|---|
| 接收年报/季报 | ✅ 用户在会话中投递 | ❌ 不提供上传入口 |
| 解析文件、识别报告期、抽取指标 | ✅ | ❌ |
| 勾稽校验 | ✅ 执行 | ✅ 呈现结果、标记异常 |
| 生成与增量重写深度报告 | ✅ | ❌ 只做展示、版本对比、发布确认 |
| DCF 测算 | ✅ 执行并写入结果 | ✅ 展示参数与结果、保存草稿 |
| 入库、版本、来源血缘 | ✅ 写入 | ✅ 承载与展示 |
| 人工确认 / 改值 | ❌ | ✅ 唯一入口 |
| 自动获取公告（P1） | ✅ 助手执行 | ❌ 仅展示来源与处理记录 |

硬性约定：

1. 工作台界面**不出现**"上传年报""生成报告""开始抓取"按钮，对应位置改为"查看最近一次处理记录"与"在助手中继续"。
2. 工作台展示的所有结论性内容必须由助手写入并带版本号，工作台不自行拼接或推断。
3. 估值参数在工作台内可查看与调整，调整后保存为参数草稿，由助手执行重算并写回新版本；工作台不内置计算与推断逻辑。
4. 处理失败时，工作台只呈现原因与定位信息（哪份文件、哪一页、哪项校验），重试动作在助手侧发起。

## 3. 范围

### 3.1 P0：单企业完整闭环

进入条件：用户已有一家企业的若干份定期报告（或接受助手自动获取），并在**助手会话**中完成投递与企业指定。

必须打通的路径：

1. 在助手会话中投递材料 → 指定企业 → 助手完成报告期识别；
2. 助手抽取指标 → 勾稽校验 → 工作台呈现待确认清单 → 用户确认 → 入库；
3. 助手生成首版深度分析报告并写入工作台；
4. 用已确认数据做 DCF 测算并保存估值版本；
5. 后续在助手会话中补充新年报/季报 → 新增报告期 → 助手增量产出报告 v2 → 工作台提示估值需复核。

完成证据：企业详情页四个页签（概览 / 数据 / 报告 / 估值）都有内容，且任一数字可点回来源文件。

恢复路径：抽错、校验不平、文件不含目标报告期时，用户能定位问题、修正或重跑，不需要重建企业。

### 3.2 P1

- 多企业横向对比视图（对标 `_医疗器械主要经营趋势.xlsx` 的呈现方式）；
- 年报自动获取（A 股优先，见第 9 章）；
- 报告导出（Markdown / Word）、估值导出（Excel）；
- 报告章节的手工编辑与批注。

### 3.3 非目标（明确不做）

| 不做 | 原因 |
|---|---|
| 实时行情、K 线、盯盘 | 与"年度级价值研究"节奏不匹配，且引入高频数据依赖 |
| 买卖建议、目标价推送 | 合规与责任边界；工作台只呈现测算与假设 |
| 组合管理、收益归因、回测 | 属另一类产品，P0 不承载 |
| 对外发布报告 / 分发原文 PDF | 来源条款限制（尤其港股），只做内部使用 |
| 多角色权限体系 | P0 单用户；P1 再评估 |

## 5. 功能需求

### 5.1 M1 企业关键经营数据

**目的**：把用户手里的多年年报/季报，变成结构一致、口径统一、可追溯的指标库，并成为报告与估值的唯一数据源。

> 本节动作除特别说明外均由**助手**执行；工作台只呈现结果、接收确认（见 2.4）。

#### 5.1.1 材料接收（FR-D1）

| 项 | 规则 |
|---|---|
| 执行方 | **助手侧**：用户在会话中投递文件并指定企业；工作台不提供上传入口 |
| 触发 | 用户说明"这是 X 公司的 2018–2025 年报/季报"，或要求助手自动获取 |
| 支持格式 | PDF（主）、Excel、Word、图片扫描件（标记为需 OCR） |
| 批量 | 一次可投递多份（如 2018–2025 全部年报 + 若干季报） |
| 必填信息 | 指定企业（新建或选择已有）、报告期类型可自动识别但允许人工改写 |
| 处理反馈 | 助手逐份回报：已识别报告期 / 未能识别 / 疑似重复 / 缺页；工作台"处理记录"留存同一结果 |
| 禁止行为 | 不允许把不同企业的文件混入同一批次而静默处理——必须提示并阻断，要求用户确认归属 |

#### 5.1.2 指定企业（FR-D2）

- 新建企业最小字段：名称、市场（A 股 / 港股 / 美股 / 非上市）、证券代码（可空）、本位币、会计准则、报表口径（默认合并报表）。
- 若名称与库内企业高度相似（如"某某科技" vs "某某科技股份有限公司"），必须先提示"疑似已存在"，由用户选择复用或新建，避免同一公司分裂成两条记录。
- 一旦企业建立，其 `企业 + 报告期` 组合即为全库唯一键。

#### 5.1.3 报告期识别（FR-D3）

- 从文件首页与标题中识别：期间类型（年报 / 半年报 / 一季报 / 三季报）、财年、起止日期。
- 识别不确定（如标题含"摘要""（更正后）""英文版"）时，标为"待人工指定"，不猜。
- 同一 `企业 + 报告期` 已有数据时，进入**覆盖 / 并存**选择：默认"覆盖并新建版本"，旧值转入历史。

#### 5.1.4 指标抽取（FR-D4）

- 抽取范围由**指标字典**控制，不自由发挥（字典见 9.1）。分四组：
  - 利润表：营业总收入、营业收入、营业成本、毛利率、销售/管理/研发费用、营业利润、利润总额、所得税费用、净利润、归母净利润；
  - 资产负债表：货币资金、应收账款、存货、流动资产合计、固定资产、总资产、有息负债、应付账款、总负债、归母净资产；
  - 现金流量表：经营活动现金流量净额、购建固定资产等支付的现金（资本开支）、投资活动净额、筹资活动净额、现金及等价物净增加额；
  - 衍生指标：自由现金流（FCFF/FCFE）、ROE、ROIC、净利率、资产负债率、营收/利润复合增速（由系统按公式计算，不接受人工直接改值）。
- 每个指标值必须记录：来源文件、页码/表名、原始单位与原始币种、是否合并报表、是否经审计、置信度。
- 抽不到就是"缺失"，**不允许用 0 或估算值填充**；缺失项在矩阵中显示为"待补"。

#### 5.1.5 校验与置信度（FR-D5）

校验规则见 9.4，不通过项不阻断入库，但：

- 计入"待确认"，并在企业卡片上显示红色计数；
- 涉及估值的必需指标，不得进入"已确认"以外的状态被估值引用。

置信度分级：

| 级别 | 判定 | 处理 |
|---|---|---|
| 高 | 表格结构清晰、与勾稽规则一致、同一数字在摘要与正文一致 | 可直接批量确认 |
| 中 | 结构可解析但存在单位/合并范围歧义，或仅有单处出现 | 需逐项确认 |
| 低 | 扫描件 OCR、跨页断表、数字缺失或多版本冲突 | 必须人工录入或核对后确认 |

#### 5.1.6 人工确认（FR-D6）

- 确认界面以"报告期 × 指标"列表呈现，支持按"仅看异常"过滤。
- 每个单元格可展开：原文件截图/原文片段、抽取值、历史值、校验提示。
- 支持三种动作：确认、改为人工值（留痕并注明原因）、标为争议（挂起，不参与估值）。
- 批量确认只允许对"高置信度且勾稽通过"的项生效。
- 确认人与确认时间必须记录；后续任何修改产生新的指标值版本，旧值不删除。

#### 5.1.7 入库与展示（FR-D7）

- 入库后 `企业 + 报告期 + 指标` 只有一个"当前有效值"，历史值可在"版本与来源"中查看。
- 数据页默认展示：行=指标（按报表分组）、列=报告期（按时间倒序或正序可切换）、单元格=数值 + 单位 + 状态点。
- 支持视图切换：数值视图 / 同比视图 / 占营收比视图 / 图表视图。
- 每个数字可点击查看来源与血缘。

#### 5.1.8 异常与边界

| 情况 | 处理 |
|---|---|
| 文件不含任何财务三表（如只有文字公告） | 批次标"不可用"，提示用户更换文件 |
| 同一报告期投递了"报告 + 摘要 + 更正版" | 以"更正版 > 报告 > 摘要"为权威，其余作为附件保留并标注 |
| 单位不一致（元 / 千元 / 万元 / 百万元） | 统一换算到元存储，原文单位保留展示 |
| 币种不一致（HKD/USD/CNY） | 保留原币值；跨币种比较与估值时按指定汇率换算，汇率来源与日期必须记录 |
| 抽取批次中途失败 | 已成功文件保留、失败文件可单独重试，不要求整批重来 |

### 5.2 M2 企业深度分析报告

**目的**：把"数据 + 判断"沉淀成一篇可持续迭代的长文，随新年报增量生长，而不是每次从零重写。

> 报告由**助手**生成与重写；工作台负责展示、版本对比与发布确认（见 2.4）。

#### 5.2.1 报告模板（章节骨架）

模板为可配置对象，默认骨架如下（**待用 `2017_海康威视_深度分析文章.docx` 校准** `[Assumption, TBD]`）：

| 章节 | 内容要求 | 数据来源 |
|---|---|---|
| 0 摘要与结论 | 一句话生意本质、当前判断、估值区间与安全边际 | 全文提炼 |
| 1 公司概况与业务结构 | 主营构成、收入拆分、客户与区域、商业模式 | 年报"业务讨论" + 收入拆分指标 |
| 2 行业与竞争格局 | 行业空间、竞争位置、份额变化 | 行业数据 + 用户补充材料 |
| 3 经营表现 | 5–10 年营收/利润/毛利率/费用率趋势，异常年份解释 | 指标库 |
| 4 财务质量 | 现金流与利润匹配度、应收/存货、负债结构、ROE/ROIC 拆解 | 指标库（含勾稽结果） |
| 5 成长驱动与风险 | 增长来源、可验证的跟踪指标、主要风险 | 数据 + 定性判断 |
| 6 现金流与估值 | FCFF 历史、DCF 假设与结果、敏感性、与当前价格对比 | 估值模块 |
| 7 跟踪清单与结论 | 下个报告期需要验证的 3–5 个点 | 上文推导 |

规则：

- 每个结论性段落必须能"点开看数"，引用格式统一为"指标 + 报告期 + 值"；
- 无法用数据支撑的判断，必须显式标为"观点"；
- 报告里不出现没有来源的外部数字；需要外部数据时进入"待补资料"清单。

#### 5.2.2 生成（FR-R1）

- 触发：某企业存在"已确认"的、覆盖至少 3 个年度的核心指标。
- 生成前检查：估值必需指标完整度、勾稽未通过项、争议项；不满足项以"报告附注：以下数据待确认"呈现，不阻断出稿。
- 结果：由助手生成 v1 草稿并写入工作台，交由用户审阅。

#### 5.2.3 增量合并重写（FR-R2）

用户在助手会话中补充新报告期后：

| 步骤 | 规则 |
|---|---|
| 1 识别新增期 | 新报告期进入指标库并完成确认 |
| 2 章节级影响判定 | 每个章节标注：无需修改 / 数据刷新 / 结论改写 |
| 3 增量重写 | 以**上一版全文为底稿**，只改写受影响章节；未受影响章节原文保留并标注"沿用 v2" |
| 4 变更标注 | 新增/修改段落以差异标记呈现，并生成"本版变更摘要" |
| 5 一致性回查 | 摘要结论、估值章节、跟踪清单必须与新数据一致，否则阻断发布 |

硬规则：

- **不允许整篇重新生成**导致既有判断被无声替换；
- 若新数据与上一版结论方向相反（如由"增长"变"下滑"），必须生成"结论变更提示"，要求用户显式确认后才可发布；
- 新报告期若触发历史数据重述（见 8.2），受影响的旧章节必须重算，并在变更摘要中列出。

#### 5.2.4 版本与对比（FR-R3）

- 每版记录：版本号、基于的报告期集合、数据快照、变更摘要、生成与发布时间、发布人。
- 支持"与上一版对比"：并排或行内差异，按章节过滤。
- 支持回滚：把任一历史版本"提升为当前版本"（生成新版本号，内容取自旧版），不删除中间版本。
- 已发布版本只读。

#### 5.2.5 引用与可追溯（FR-R4）

- 报告中每个被引用的数字，点击可跳到该指标值的详情（来源文件 + 页码 + 确认状态）。
- 若某数字在报告发布后被改为新版本，报告页顶部出现"引用数据已更新，建议出新版"提示，但不自动改写正文。

### 5.3 M3 自由现金流（DCF）估值模型

**目的**：用工作台内已确认的数据做可复用、可回溯的估值，而不是在外部 Excel 里重搭一遍。

> 测算由**助手**执行；工作台负责展示参数与结果、保存参数草稿（见 2.4）。

#### 5.3.1 数据准备（FR-V1）

- 输入只来自指标库中状态为"已确认/已锁定"的指标值；"争议/待确认"项不可选。
- 基准报告期默认取"最近一个已确认年报"，可改选；季报仅用于最新一年年化提示，不直接作为 DCF 起点。
- 数据不足时，估值页显示缺口清单并禁止生成结果（允许保存草稿参数）。

#### 5.3.2 参数（FR-V2）

| 参数组 | 参数 | 默认来源 | 可编辑 |
|---|---|---|---|
| 预测期 | 显式预测年数（默认 5 年，可选 5–10） | 产品默认 | 是 |
| 增长 | 未来 3 年营收增速、之后逐年收敛 | 历史 3 年复合增速 `[Assumption]` | 是 |
| 盈利能力 | 营业利润率、实际税率 | 最近 3 年均值 | 是 |
| 再投资 | 资本开支/营收、折旧摊销/营收、营运资本变动/营收 | 最近 3 年均值 | 是 |
| 折现 | WACC（或由无风险利率 + 风险溢价 + 债务成本加权得出） | 用户输入为主 | 是 |
| 永续 | 永续增长率 g（须 < WACC，且给出上限提示） | 产品默认 2%–3% `[Assumption, TBD]` | 是 |
| 调整项 | 净负债、少数股东权益、非经营性资产、总股本 | 指标库自动带入 | 是（须留痕） |
| 汇率 | 外币企业折算汇率与日期 | 用户指定 | 是 |

#### 5.3.3 测算（FR-V3）

- 自由现金流口径二选一，默认 FCFF：`FCFF = EBIT×(1−税率) + 折旧摊销 − 资本开支 − 营运资本增加`。
- 企业价值 = 显式期 FCF 折现之和 + 终值折现；终值采用永续增长法 `TV = FCFₙ×(1+g)/(WACC−g)`。
- 股权价值 = 企业价值 − 净负债 + 非经营性资产 − 少数股东权益；每股价值 = 股权价值 ÷ 总股本。
- 结果必须同时展示：每股价值、市值隐含假设、与当前价格对比的安全边际（若用户录入价格）、中间年度 FCF 预测表。
- 每个中间量都可展开看公式与代入口径，避免"黑箱出一个数字"。

#### 5.3.4 敏感性（FR-V4）

- 默认输出 WACC × 永续增长率 的二维敏感性矩阵（如 WACC 8%–12%、g 1%–4%）。
- 可选第二组：营收增速 × 营业利润率。
- 结果以色阶呈现，标出"基准情景区间"。

#### 5.3.5 版本与联动（FR-V5）

- 每次保存生成估值版本，记录参数快照与所引用的指标值版本。
- 上游数据变化（新增报告期、历史重述、指标改值）时：估值版本标"待复核"，**不自动改写结论**；用户选择重算后，由助手按新数据生成新版本。
- 同一企业可并存多套模型（如保守/中性/乐观），每套独立版本线。

#### 5.3.6 边界

| 情况 | 处理 |
|---|---|
| 自由现金流为负或不稳定 | 提示"DCF 不适用或需改用分部估值"，允许保存但不给结论徽标 |
| 金融类企业 | 明确标注"FCF 口径不适用"，P0 不提供专门模型 |
| 永续增长率 ≥ WACC | 阻断并提示参数不合理 |
| 总股本缺失 | 阻断每股价值计算，仅给企业价值 |
| 外币报表 | 强制要求汇率，结果同时给原币与本币 |

## 6. 端到端流程

### 6.1 首次建企（S1）

```
用户在助手会话中投递 N 份年报/季报
   ↓
用户指定企业（新建 or 复用）＋ 确认市场/币种/准则
   ↓
助手识别报告期 → 回报"已识别 / 待指定 / 重复 / 不可用"
   ↓
用户确认清单 → 助手启动抽取
   ↓
助手抽取完成 → 勾稽校验 → 工作台呈现"待确认清单"（异常优先排序）
   ↓
用户在工作台确认（或修正）→ 指标入库
   ↓
助手生成报告 v1 草稿并写入工作台 → 用户审阅 → 发布
   ↓
进入估值页 → 查看/调整假设 → 助手测算 → 保存估值 v1
```

完成判定：工作台首页企业卡片显示覆盖期数、报告版本、估值结论；任一数字可回溯来源。工作台自身不执行任何解析或生成动作。

### 6.2 增量续更（S3）

```
用户在助手会话中投递新年报/半年报/季报 → 指定同一企业
   ↓
助手判定报告期：新增 / 已存在（覆盖）/ 更正月
   ↓
助手增量抽取 → 只校验新增期 + 受重述影响的旧期
   ↓
用户在工作台确认 → 入库（旧期数据不变，或按重述规则生成新版本）
   ↓
助手做章节级影响判定 → 增量重写 → 出 v(n+1) 草稿 → 工作台差异视图 → 发布
   ↓
估值：所有版本标"待复核" → 用户选择重算 → 助手测算 → 出估值 v(m+1)
```

关键规则：**数据、报告、估值三者各自版本化，通过"基于哪一版数据"建立引用关系，不互相静默覆盖。**

### 6.3 新增企业（S4）

与 6.1 完全一致，只是企业为新建；投递同样在助手会话中发起，不允许把新企业文件并入既有企业批次。

### 6.4 失败与恢复

| 失败点 | 用户可见 | 恢复动作 |
|---|---|---|
| 文件无法识别报告期 | 该文件标"待指定"，其余文件继续 | 在助手中指定期间后单独重跑 |
| 抽取置信度低 | 进入待确认，高亮 | 对照原文修正并确认 |
| 勾稽不平 | 标"校验不通过"，列出差额 | 选择正确列（本期/上期）或改值 |
| 批次中途中断 | 已成功部分保留 | 在助手中仅重试失败文件 |
| 报告生成失败（数据不足） | 展示缺口清单 | 补齐数据后在助手中重新生成 |
| 估值参数不合理 | 就地提示，不允许保存结论 | 调整参数 |

## 8. 增量更新与历史版本规则

### 8.1 唯一键与去重

| 对象 | 唯一键 |
|---|---|
| 报告期 | 企业 + 期间类型 + 财年 + 期内序号 |
| 指标值 | 企业 + 报告期 + 指标 + 版本 |
| 来源文件 | 文件哈希（同哈希不重复入库） |
| 报告版本 | 企业 + 版本号（自增，不复用） |
| 估值版本 | 模型 + 版本号（自增） |

### 8.2 指标变更的三种情形

| 情形 | 判定 | 处理 |
|---|---|---|
| 新增报告期 | 出现新的 `企业 + 报告期` | 只新增，不动历史；报告进入增量重写；估值标"待复核" |
| 更正 / 追溯重述 | 同一报告期出现"更正后"版本，或新年报的上期数与库内不一致 | **不覆盖**：旧值归档为 v(n)，新值入 v(n+1)，记录差额与原因；受影响历史期一并重算并标记 |
| 口径变更 | 用户修改企业口径（合并→母公司、币种、准则） | 需要显式确认，生成"口径变更批次"，全量重算并保留旧口径快照，避免趋势断裂 |

### 8.3 报告增量合并规则

1. 以"当前发布版本"为底稿，不新起空白文档；
2. 只重写受影响章节，其余章节标注"沿用 vN"；
3. 每版必须生成 `change_summary`：新增了哪些期、改写了哪些结论、哪些数字变了；
4. 结论方向发生反转时，必须人工确认才能发布；
5. 引用数字在发布后被改值 → 报告顶部提示"引用数据已更新"，不自动改正文。

### 8.4 估值重算规则

| 触发 | 系统行为 | 用户行为 |
|---|---|---|
| 新增报告期 | 标记"待复核"，保留旧结果 | 选择"按新数据重算"或"维持原假设" |
| 历史重述 | 标记"数据口径已变"，并列展示新旧结果 | 确认采用哪一版 |
| 修改参数 | 生成新版本，旧版本保留 | 可对比两版差异 |
| 数据不足 | 禁止出结论 | 补齐数据 |

### 8.5 版本可见性与回滚

- 所有版本永久可查（除用户显式删除企业）；
- 报告与估值支持"以旧版为模板生成新版"，而不是指针回退；
- 删除企业属于不可逆动作，需二次确认并保留 30 天回收站 `[Assumption, TBD]`。

## 9. 数据质量与口径

### 9.1 指标字典是唯一口径来源

- 所有指标必须先定义后使用；新增指标需给出中文名、定义、单位、是否估值必需。
- 同一含义的不同叫法（营业总收入 / 营业收入；净利润 / 归母净利润）在字典中显式区分，不允许混用。
- 衍生指标由公式计算，用户只能改输入，不能直接改输出。

### 9.2 单位与币种

| 规则 | 说明 |
|---|---|
| 存储 | 统一换算为"元"存储（`normalized_value`），同时保留原文值与原文单位 |
| 展示 | 默认按"亿元"展示，可切换万元/元；百分比保留 2 位小数 |
| 币种 | 保留原币；跨币种比较与估值必须指定汇率与汇率日期，并展示在结果旁 |
| 精度 | 金额保留原始精度，计算过程不提前四舍五入；展示层统一四舍五入 |

### 9.3 审计与报表口径

| 项 | 规则 |
|---|---|
| 报表类型 | 默认合并报表；母公司报表单独存储，不混用 |
| 审计状态 | 年报默认"经审计"，半年报/季报默认"未经审计"，以文件实际表述为准 |
| 估值取数 | 显式预测起点只用已确认年报；季报用于"最新进展"提示，不直接进 DCF |
| 列选择 | 本期/上期/年初数三列并存，抽取必须记录取的是哪一列 |
| 多版本 | "更正后 > 正式报告 > 摘要 > 英文版"作为权威顺序，其余保留为附件 |

### 9.4 勾稽校验清单

| 校验 | 规则 | 不平处理 |
|---|---|---|
| 资产 = 负债 + 所有者权益 | 完全相等（允许 1 元以内舍入差） | 阻断确认，提示可能取错列 |
| 营业总收入 ≥ 营业收入 | 恒成立 | 提示口径异常 |
| 利润总额 × (1−税率) ≈ 净利润 | 允许合理差异 | 提示税率异常 |
| 经营 + 投资 + 筹资净额 ≈ 现金及等价物净增加额 | 允许小额差异 | 提示跨表取数错误 |
| 期末现金及等价物 ≈ 货币资金 | 允许口径差（受限资金） | 提示需人工判断 |
| 归母净利润 ≤ 净利润 | 恒成立 | 阻断确认 |
| 多年趋势连续性 | 相邻期变动超过阈值（如 ±50%） | 高亮，要求填写原因 |

### 9.5 人工确认分级

| 级别 | 范围 | 是否阻断后续 |
|---|---|---|
| 必确认 | 估值必需指标、勾稽不平项、更正版差异项、低置信度项 | 阻断估值，不阻断报告出稿（报告附注标注） |
| 建议确认 | 中置信度、非估值必需但用于报告结论的指标 | 不阻断，界面提示 |
| 免确认 | 高置信度且勾稽全部通过 | 可批量确认 |

### 9.6 错误处理与留痕

- 所有人工修改记录：原值、新值、原因、操作人、时间；
- 任何状态回退（已确认 → 待确认）需说明理由；
- 报告与估值发布时冻结当时的数据快照，事后改数不影响已发布版本的可复现性。

## 10. 待确认点专项：年报能否由助手直接下载？

### 10.1 直接结论

**可以，但不能一概而论。** A 股与美股有较高把握做到"给代码/名称即自动取报告并解析"；港股技术上可抓取但受使用条款约束，需限定内部使用；三个市场都存在"抓得到 ≠ 抽得准"的问题，必须保留人工校验环节。

### 10.2 有把握的结论（可写入产品承诺）

| 市场 | 结论 | 依据 |
|---|---|---|
| A 股 | 公告检索与 PDF 下载可程序化；巨潮公开检索无登录、无验证码，PDF 为静态直链；上交所/深交所页面可作备通道 | 巨潮检索接口与详情页正文可读；沪深受 Referer/来源校验限制但可绕过常规请求头 |
| A 股 | **全量结构化三表不能白拿**：官网仅提供部分在线查询，全量 XBRL 需授权或付费数据源 | 上交所公告服务确有 XBRL 实例文档，但沪深未开放全量下载 |
| 港股 | 披露易检索接口返回 JSON、PDF 路径规则固定，可自动获取 | `prefix.do` 取 stockId、`titleSearchServlet.do` 返回含 `FILE_LINK` 的 JSON |
| 港股 | **有条款风险**：使用条款限制下载、复制、向第三方分发及编制系统性检索库 | 港交所使用条款第 5 条 |
| 美股 | EDGAR 官方 API 可直接拿结构化财务数据（`companyfacts` / `companyconcept`），原文归档路径规则清晰，可追溯到 1994/1995 年 | SEC 官方数据接口 |
| 美股 | 限速 10 请求/秒、必须带真实 UA 与联系方式，超限会被封 IP；外国私人发行人用 20-F/6-K，**季报天然不完整** | SEC 官方说明 |
| 全市场 | 定期报告存在"摘要 / 更正后 / 英文版"等变体，必须按标题关键词二次过滤并确定权威版本 | 三地公告命名规律 |
| 全市场 | 解析难点集中在：扫描件无文字层、资产负债表左右分栏与跨页、单位/币种/负号写法不一致、合并与母公司口径 | 财报版式共性 |

### 10.3 需要验证的假设（不可当作承诺）

| 编号 | 假设 | 为什么需要验证 |
|---|---|---|
| A-01 | 巨潮接口长期稳定、请求头校验策略不会收紧 | 接口非官方开放协议，属页面接口 `[Assumption]` |
| A-02 | 目标企业历史报告可一次性批量取全（含早期年份） | 早期报告可能为扫描件或缺失附件 `[Assumption]` |
| A-03 | "更正后"版本能被稳定识别，且不会出现同日多份更正 | 命名不统一，需要规则库持续维护 `[Assumption]` |
| A-04 | 港股"仅内部个人研究使用"可满足条款边界 | 属法律判断，需法务确认 `[TBD]` |
| A-05 | 用户能接受"机器提取 + 人工抽查"而非零人工 | 影响是否必须采购授权结构化数据 `[TBD]` |

### 10.4 推荐默认策略

**双通道 + 分级信任 + 分市场开关：**

| 市场 | 默认策略 | 说明 |
|---|---|---|
| A 股 | 默认自动获取（巨潮为主、交易所为备），用户上传可覆盖 | 限速 ≥1.5 秒/请求，遇 403 指数退避并停止当日批量 |
| 美股 | 默认自动获取，**优先取 XBRL 结构化数据**，原文 PDF 作报告与兜底 | ≤10 请求/秒，携带真实 UA 与联系邮箱 |
| 港股 | 默认关闭自动获取，需用户显式开启并确认"仅内部使用" | 低频（≥2 秒）、只落库不对外分发原文 |
| 通用 | 自动获取结果一律标记来源、置信度，进入"待确认"；估值必需指标必须"已确认"才可用 | 抓取失败或解析置信度低 → 自动降级为"请上传" |

一句话的默认答案：**"你不需要提供年报，助手可以自己下载；但下载到的数据默认是待核对状态，估值前关键指标仍要你点一下确认。"**

### 10.5 与产品流程的衔接

- 投递与抓取都由**助手**执行：用户在会话中上传文件，或直接说明"用代码 600519 自动获取 2018–2025 年报"；两者进入同一抽取批次流程；
- 自动获取的每份文件记录 `source_url / announcement_id / 披露日期 / 抓取时间 / 文件哈希`；
- 若自动获取到的报告与用户上传件冲突，以用户上传为权威，差异进入"待确认"；
- 工作台只读展示处理记录与来源，不提供上传、抓取、重试按钮；批量抓取在助手侧执行，完成后结果落入工作台。

| 阶段 | 目标 | 范围 | 验收标志 |
|---|---|---|---|
| P0 | 单企业闭环跑通 | 会话投递（助手侧抽取）、指标字典、校验与人工确认、数据视图、报告 v1 + 增量版本、DCF + 敏感性、版本与来源 | 用 1 家真实企业（3 年以上报告）走完 S1→S2→S3，数字全部可回溯 |

排序理由：先保证"数据可信 + 版本可回溯"，再追求"少手工"。自动获取若先于确认机制上线，会放大错数风险。
