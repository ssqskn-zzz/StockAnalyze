## 3. 渠道清单（可直接落地的技术事实）

### 3.1 A 股

**首选：巨潮资讯网（cninfo，证监会指定披露平台，覆盖沪深主板/创业板/科创板/北交所）**

- 检索接口：`POST https://www.cninfo.com.cn/new/hisAnnouncement/query`
- 关键参数：`stock`（代码与 orgId，逗号分隔）、`column`（`sse`/`szse`/`bj`）、`category`（`ndbg` 年报 / `bndbg` 半年报 / `yjdbg` 一季报 / `sjdbg` 三季报）、`seDate`（`YYYY-MM-DD~YYYY-MM-DD`）、`pageNum`、`pageSize`、`searchkey`、`sortName=time&sortType=desc`
- 返回字段：`announcementTitle`、`announcementId`、`announcementTime`、`adjunctUrl`、`adjunctSize`、`adjunctType`、`secCode`、`orgId`
- PDF 直链：`https://static.cninfo.com.cn/{adjunctUrl}`（文件名形如 `finalpage/2026-10-31/1225649896.PDF`）
- 详情页：`https://www.cninfo.com.cn/new/disclosure/detail?announcementId=...&stockCode=...&orgId=...`，**实测该页直接给出报告正文文本**（茅台 2026 三季报正文可读），可作为 PDF 之外的第二取数通道
- 登录/验证码：公开检索**不需要登录、无验证码**；但校验 `User-Agent`/`Referer`，短时间高频请求返回 403
- 实测社区实践：内置请求间隔 **1.5 秒**；偶发需浏览器 Cookie 才能下 PDF；附件可能是 PDF/HTML/XLSX，需按 `adjunctType` 过滤
- 检索命名规律：标题含 `YYYY年年度报告`、`YYYY年半年度报告`、`YYYY年第一季度报告`、`YYYY年第三季度报告`，并存在 `摘要`、`（更正后）`、`英文版` 等变体，**必须按标题关键词二次过滤**

**上交所（sse.com.cn）**

- 公司公告 JSON：`http://query.sse.com.cn/security/stock/queryCompanyBulletinNew.do`（JSONP）
- **实测无 Referer 直接请求返回** `{"success":"false","error":"系统繁忙...","errorType":"ExceptionInterceptor"}`；必须带 `Referer: http://www.sse.com.cn/` 及正常 UA
- 定期报告栏目：`http://www.sse.com.cn/disclosure/listedinfo/regular/`
- PDF 静态路径规律：`/disclosure/listedinfo/announcement/c/new/YYYY-MM-DD/{代码}_{YYYYMMDD}_{ID}.pdf`
- 无登录、无验证码，本质是 Referer 白名单反爬

**深交所（szse.cn）**

- 公告接口：`POST https://www.szse.cn/api/disc/announcement/annList`（JSON 请求体，需 `Referer: https://www.szse.cn/` 与 ajax 头）
- **实测无头直接 GET 返回空内容**，说明接口有来源校验
- 定期报告专页：`https://www.szse.cn/disclosure/listed/fixed/index.html`（实测可读，逐条列出代码/简称/标题/大小，PDF 图标）
- 详情页：`/disclosure/listed/bulletinDetail/index.html?{uuid}`；PDF 走 `disc.static.szse.cn`

**结构化数据（重要）**

- 上证所信息网络有限公司公告服务明确提供：全文 WORD、摘要 WORD、全文 PDF、摘要 PDF、**XBRL 实例文档**
- 但据行业研究（2024）：沪深官网仅提供 XBRL 分类标准与部分在线查询/比对，**未开放全量 XBRL 文档下载**；北交所/股转既未公布标准也未提供下载
- 结论：要"免解析拿三张表"，A 股要么走**授权数据源**（深证信/巨潮数据服务 `webapi.cninfo.com.cn`，需申请与付费），要么自行解析 PDF

### 3.2 港股（披露易 HKEXnews）

- 代码→内部 ID：`GET https://www1.hkexnews.hk/search/prefix.do?callback=cb&lang=ZH&type=A&name=00700&market=SEHK` → `{"stockId":7609,"code":"00700","name":"騰訊控股"}`（**实测可用**）
- 公告检索：`GET https://www1.hkexnews.hk/search/titleSearchServlet.do?sortDir=0&sortByOptions=DateTime&category=0&market=SEHK&stockId={stockId}&documentType=-1&fromDate=&toDate=&title=&searchType=1&t1code=40000&t2Gcode=&t2code=&rowRange=100&lang=zh`
- **实测直接返回 JSON**，字段含 `TITLE`、`DATE_TIME`、`FILE_INFO`（大小）、`FILE_TYPE`、`LONG_TEXT`（分类）、`FILE_LINK`
- `t1code=40000` 实测对应"財務報表／環境、社會及管治資料"，结果中含 `[年報]`、`[中期/半年度報告]`、`[ESG 報告]`，需再按 `LONG_TEXT` 细分
- PDF 直链：`https://www1.hkexnews.hk{FILE_LINK}`，形如 `/listedco/listconews/sehk/2026/0417/2026041700412_c.pdf`（`_c` 中文版、`_e` 英文版）
- 登录/验证码：**无**；但**无官方 API、无公开限额说明**
- **条款风险**：港交所使用条款第 5 条明确，未经书面许可不得下载、复制、向第三方分发网站资料，或用其编制衍生作品/系统性检索库

### 3.3 美股（SEC EDGAR）

- 公司提交历史：`https://data.sec.gov/submissions/CIK##########.json`（CIK 补足 10 位，实测可返回完整 filing 列表）
- 结构化财务：`https://data.sec.gov/api/xbrl/companyfacts/CIK##########.json`、`companyconcept/.../us-gaap/{tag}.json`
- 原文归档：`https://www.sec.gov/Archives/edgar/data/{cik}/{accessionNumber 去横线}/{primaryDocument}`
- 索引文件：`/Archives/edgar/full-index/`、`daily-index`，每个目录均有 `index.json` 供程序化抓取；数据可追溯至 1994/1995 年
- 限流与身份（官方原文要点）：
  - **当前上限 10 请求/秒**（按用户，不按机器数）
  - 必须声明 `User-Agent`，格式示例 `Sample Company Name AdminContact@example.com`；默认库 UA 常被封
  - 超限/违规会**封 IP**，SEC 保留限制速率与阻断的权利；403/429 需退避
  - 免费、无需 Key；SEC 不提供脚本调试技术支持
- 表单口径：本土公司用 **10-K / 10-Q**；外国私人发行人用 **20-F / 6-K**，**通常没有 10-Q**，季报完整性天然不足

## 4. PDF 解析难度与数据口径

### 4.1 文本版 vs 扫描版

- A 股 2010 年后定期报告基本是**带文字层的 PDF**，可直接抽文本与表格；巨潮详情页实测已给出可读正文
- 早期报告、部分港股附件、美股 exhibit 仍有**扫描件**（无文字层），必须 OCR；需先做"是否含文字层"检测，再分流处理
- 扫描件典型问题：倾斜、印章压字、模糊，OCR 错字率高，数字识别错误直接影响估值

### 4.2 表格抽取的常见坑

- 资产负债表天然左右分栏（资产 | 负债及权益），跨页拆表常见，通用抽取器易"半张表 / 列错位 / 丢小计行"
- 多级表头、合并单元格、无边框靠缩进对齐 → 版式各异，需要逐模板适配
- 单位不统一：元 / 千元 / 万元 / 百万元 / 千美元，且表头与表内可能不一致
- 负号写法：`-`、`—`、`(123)`、全角字符、千分位逗号混排
- 脚注、附注编号混入单元格；"不适用"、"-"与 0 含义不同（如现金流量表"不适用"）

### 4.3 中文财报三张表的口径问题（对 FCF 模型影响最大）

- **合并报表 vs 母公司报表**：默认取合并；母公司表在部分分析中另有用，误取会系统性偏差
- **本期 / 上期 / 年初数**三列并存，跨表勾稽要选对列
- **追溯重述与会计差错更正**：公司可能对往年报表追溯调整（实测公告常见"追溯重述法""调减营业收入/成本"），历史库必须允许覆盖重算并保留版本，否则多年趋势断裂
- 科目口径：`营业总收入` vs `营业收入`、`净利润` vs `归母净利润`、少数股东权益、研发费用资本化
- 准则差异：A 股 CAS、港股 IFRS/HKFRS、美股 US GAAP；同一指标（如经营现金流、有息负债）需统一映射
- 币种差异：港股常见 HKD/CNY/USD 混用，估值前必须统一
- 更正版问题：同一报告期可能先后出现"报告""摘要""（更正后）""英文版"，需以最新更正版为权威并记录公告 ID

## 5. 分市场可行性结论与建议


| 市场  | 自动获取              | 自动解析                  | 最终判断                    | 建议做法                                          |
| --- | ----------------- | --------------------- | ----------------------- | --------------------------------------------- |
| A 股 | 高（接口稳定、无登录）       | 中（文本版可解析，表格需模板+校验）    | **可直接自动获取，辅以人工校验**      | 巨潮为主通道、交易所页面为备通道；报告下载后先抽三张表，做勾稽校验，首年抽检 20% 样本 |
| 港股  | 高（JSON 检索、路径规则固定） | 中偏低（无结构化数据、多为繁体且版式自由） | **可自动获取，建议人工校验；仅限内部自用** | 低频抓取（≥2s）、只落库不对外分发原文；解析结果标注"待人工确认"            |
| 美股  | 很高                | 高（XBRL 直接给结构化数据）      | **可直接自动获取，优先结构化**       | 先取 `companyfacts`，PDF 仅作报告与兜底；注意 20-F/6-K 无季报 |


**产品形态建议（与"价值投资工作台"对应）**

1. **双通道**：默认"自动获取"，同时保留"用户上传"入口；自动失败（限流、格式异常、解析置信度低）时自动降级为上传。
2. **来源可追溯**：每条记录保存 `source_url`、`announcementId`、披露日期、抓取时间、文件哈希、报告期、版本（初版/更正版），报告页显示出处。
3. **解析可信度分级**：三张表逐项打分，做整数级勾稽（资产=负债+权益；净利润衔接；期末现金≈货币资金），不通过即转人工，不静默采用。
4. **限速与礼让**：cninfo ≥1.5s/请求、SEC ≤10 rps 且带真实 UA 与联系邮箱、HKEXnews ≥2s；遇 403/429 指数退避并停止当日批量任务。
5. **增量更新**：按"股票代码 + 报告期 + category"做唯一键，定期扫描新增公告；发现"更正后"版本触发重算与报告再生成。
6. **合规边界**：原文仅内部存储与展示引用，不对外提供批量下载/再分发；港股条款最严，需在方案评审时单独确认。

## 6. 关键风险


| 风险      | 表现                          | 缓解                                |
| ------- | --------------------------- | --------------------------------- |
| 限流/封禁   | A 股 403、SEC 封 IP、接口临时不可用    | 限速、退避、多通道切换、缓存已下载文件               |
| 法律合规    | 港股条款禁止下载/再分发；A 股页面版权归交易所/公司 | 仅内部使用、不二次分发原文、标注出处、必要时采购授权数据      |
| 格式异构    | 版式逐年变化、扫描件、HTML/XLSX 附件     | 模板库 + 文字层检测 + OCR 兜底 + 置信度阈值      |
| 口径不一致   | 合并/母公司、单位、币种、准则、重述          | 统一科目映射表 + 人工规则审核 + 版本化重算          |
| 数据准确性责任 | 抽错一个数字即影响估值结论               | 勾稽校验、抽样复核、界面标注"机器提取，待核对"、保留人工修改留痕 |
| 披露时点    | 预约披露、更正公告、英文版滞后             | 以公告时间为准做版本排序，只在"最新版"上出结论          |
