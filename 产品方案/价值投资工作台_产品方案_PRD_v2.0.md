## 0. 阅读指引与本次校准说明

### 0.1 术语（全文统一口径）

| 术语 | 定义 |
|---|---|
| 企业 | 一家被分析的主体，可上市（A 股 / 港股 / 美股）或非上市；工作是围绕"企业"这一容器展开 |
| 企业池 | 一批被粗筛过的企业集合，只承载"快速比较 + 进入深研"的入口，不承载正式数据与报告 |
| 报告期 | 一个财务期间，如"2024 年年度报告""2025 年半年度报告""2025 年第三季度报告" |
| 指标（指标项） | 指标字典中的一个受控条目，如"营业总收入""扣非净利润"，带固定定义、单位与维度 |
| 指标值 | 某企业在某报告期、某维度上的一项指标取值，是**最小可追溯、可确认、可版本化**的数据单元 |
| 维度 | 指标值的拆分口径：合计 / 分产品 / 分区域 / 分渠道；如"营业收入·前端产品·2017" |
| 数据快照 | 一次"确认入库"完成后冻结的指标值集合标签；报告版本与估值版本都引用它，用于回答"这一版结论用了哪一版数据" |
| 抽取批次 | 用户一次投递（可含多份文件）或一次自动获取触发的处理任务集合 |
| 报告版本 | 深度分析报告的一次完整快照，新版本不覆盖旧版本 |
| 估值版本 | DCF 模型的一次"参数 + 基准数据 + 结果"快照 |
| 确认状态 | 指标值的可信状态：机器提取 → 待确认 → 已确认 → 已锁定 |
| 数据血缘 | 指标值来自哪份文件、哪张表、哪一页、取的是哪一列、由谁在何时修改 |

标注约定：`[样本事实]` 表示直接来自三份参考样本的解析内容；`[提案]` 表示产品设计建议，样本未直接证实；`[TBD]` 表示需用户决策（汇总见第 16 章）。

**由样本推导出的三个产品判断** `[提案]`：
1. 用户的真实工作流是**两段式**：先用全市场企业池做"股权价值 vs 市值"的粗筛，再对少数标的做深度分析 —— v1.1 只覆盖了第二段，v2.0 需补第一段的**轻量形态**（企业池，P1）；
2. 报告的默认骨架应采用样本的 **7 部分结构**，而不是 v1.1 的 8 章结构；
3. 估值默认口径应采用样本的**简化股东现金流口径**，FCFF 作为并列可选口径，而不是反过来。

## 1. 产品定位与目标用户

### 1.1 一句话定位

把"读年报 → 提数据 → 写分析 → 做 DCF"这条原本散落在 Excel、Word 和个人记忆里的工作流，收拢成一个**按企业沉淀、可增量更新、可追溯版本**的价值投资研究工作台。

解析、抽取、写作、测算全部在**助手侧**完成；工作台只负责承载结果、管理版本、呈现口径与收集人工确认。

### 1.2 三块能力的一句话定义（本次需求的核心）

| 能力 | 一句话定义 | 承载物 | 谁生产 | 谁消费 |
|---|---|---|---|---|
| M1 企业关键经营数据 | 把 N 年定期报告变成口径统一、可按年/按季/按产品/按区域查看的指标库 | 指标值 + 数据快照 | 助手抽取 | 报告、估值、用户查数 |
| M2 企业深度分析报告 | 把数据与判断沉淀成一篇可随新材料持续演进的长文 | 报告版本（只增不改） | 助手撰写 | 用户阅读、评审 |
| M3 自由现金流估值模型 | 用已确认数据做可复用、可回溯的 DCF 测算 | 估值版本（参数+基准+结果快照） | 助手测算 | 用户决策、报告引用 |

三者的关系是**单向依赖**：M1 是唯一事实源，M2 与 M3 都是它的下游；M2 引用 M3 的结论时只引用版本，不复制数字。

### 1.3 目标用户

| 用户 | 特征 | 核心诉求 |
|---|---|---|
| 个人价值投资者（主） | 自建 Excel 模型，长期跟踪 5–30 家企业，习惯"先全市场粗筛再深研" `[样本事实]` | 数据不重复录入、口径一致、换年时"续写"而非重写 |
| 小型研究团队（次） | 2–5 人分工覆盖行业 | 同一企业多人维护，结论与数据可追溯到来源与版本 |

### 1.4 使用场景

| 场景 | 触发 | 用户动作 | 完成标志 |
|---|---|---|---|
| S1 首次建企 | 决定研究一家新公司 | 在助手会话中给出"企业 + 报告期区间"（投递文件或让助手下载） | 企业出现在工作台，含覆盖报告期、数据矩阵、首版报告、首版估值 |
| S2 估值测算 | 数据齐备后判断贵不贵 | 在估值页确认/调整假设，由助手测算 | 得到股权价值、每股价值区间与敏感性表，且可回溯所用数据 |
| S3 同企业增量 | 新一期年报/半年报/季报发布 | 在助手会话中追加该期材料 | 新增报告期入表；报告出 v(n+1)（旧版保留）；估值标"待复核" |
| S4 新增企业 | 覆盖新标的 | 同 S1，企业为新建 | 企业列表新增一行，与既有企业互不干扰 |
| S5 粗筛（P1） | 想知道"哪些标的便宜" | 在企业池视图按"股权价值 vs 市值"排序筛选，选中者一键"转入深研" | 企业池中出现候选行；转入时创建正式企业并进入 S1 |

### 1.5 产品不做的事（摘要，详见 3.3）

不做行情看板与 K 线、不做买卖建议与目标价推送、不做组合与回测、不做自动下单、不对外分发报告与原文 PDF。

## 2. 产品模型

### 2.1 对象关系（本次新增"数据快照"与"企业池"）

```
企业池 Pool（P1，仅粗筛）
 └─(转入)→ 企业 Company
        ├── 报告期 Period ──┬── 指标值 MetricValue（带维度 / 版本 / 确认状态 / 来源）
        │                   └── 来源文件 SourceFile（年报 / 半年报 / 季报 / 更正版 / 抓取件）
        ├── 数据快照 DataSnapshot（某时点"哪些指标值被确认为有效"的冻结标签）
        ├── 深度报告 Report ── 报告版本 ReportVersion（v1..vn，只增不改）
        │                        └── 章节 Section（含"沿用自哪一版"与"本版变更类型"）
        ├── 估值模型 ValuationModel ── 估值版本 ValuationVersion（参数 + 基准数据 + 结果）
        └── 抽取批次 IngestionBatch（投递 / 抓取 → 解析 → 校验 → 确认 → 入库）
```

一句话：**指标值是唯一事实源，数据快照是"版本引用锚点"，报告与估值是快照的下游消费者。** 任一上游变更都必须能回答"影响了哪一版报告、哪一版估值"。

### 2.2 关键对象定义

| 对象 | 作用 | 关键约束 |
|---|---|---|
| 企业 | 一级容器，聚合报告期、数据快照、报告、估值 | 同一市场内证券代码唯一；无代码企业按"名称 + 成立年份"去重 |
| 报告期 | 时间轴锚点 | 唯一键 = 企业 + 期间类型 + 财年 + 期间序号 |
| 指标值 | 最小数据单元 | 必须带来源；同一(企业, 报告期, 指标, 维度)只有一个"当前有效版本"，历史版本不删除 |
| 数据快照 | 版本引用锚点 | 由一次"确认入库"产生，只增不改；报告/估值必须声明引用哪个快照 |
| 抽取批次 | 一次投递或抓取的处理单元 | 允许部分成功；失败项可定位到具体文件与页 |
| 报告版本 | 分析结论的时间切片 | 发布后不可修改，只能出新版本；定性章节不得静默沿用 |
| 估值版本 | 测算结果的时间切片 | 必须记录引用的快照、基准 FCF 口径、全部参数与市值时点 |
| 企业池 | 粗筛工作区（P1） | 只存代码/名称/粗筛指标，不存正式指标值与报告；转入深研才建企业 |

### 2.3 三块能力的功能边界（Must / Must-not）

| 能力 | 必须做（Must） | 明确不做（Must-not） |
|---|---|---|
| M1 关键经营数据 | 多年矩阵（年 + 季）、分产品/分区域/销量维度、增幅视图、确认与改值、来源定位、快照 | 不做实时行情、不做自动预测、不做同业估值比较结论 |
| M2 深度分析报告 | 7 部分骨架、数据引用可点开、版本对比、增量演进、变更摘要、定性章节复核 | 不自动对外发布、不生成买卖建议、不复制估值数字（只引用版本） |
| M3 DCF 估值 | 参数可视化、基准 FCF 多口径、分段增长、敏感性、稳定度与适用性判断 | 不做多方法估值（PE/PB 为 P1 议题）、不给目标价、不自动改写报告 |

### 2.4 处理位置与职责边界（工作台无模型能力）

工作台是**结果容器与规则界面**，不承担解析、抽取、写作、测算。这些动作全部在**助手侧**完成 —— 用户在助手会话中给出企业与非报告期区间，助手取材料、抽取、写报告，再把结果写入工作台。

| 能力 | 助手侧 | 工作台 |
|---|---|---|
| 接收/获取年报与季报 | ✅ 会话投递 或 按代码自动下载 | ❌ 不提供上传、抓取入口 |
| 解析文件、识别报告期、抽取指标 | ✅ | ❌ |
| 勾稽校验 | ✅ 执行 | ✅ 呈现结果、标记异常 |
| 生成与增量重写报告 | ✅ | ❌ 只做展示、版本对比、发布确认 |
| DCF 测算 | ✅ 执行并写入结果 | ✅ 展示参数与结果、保存参数草稿 |
| 入库、版本、快照、血缘 | ✅ 写入 | ✅ 承载与展示 |
| 人工确认 / 改值 / 争议标记 | ❌ | ✅ 唯一入口 |
| 报告定性章节"是否仍成立"的确认 | ❌ | ✅ 唯一入口 |

硬性约定（沿用 v1.1，并补充第 5 条）：

1. 工作台界面**不出现**"上传年报""生成报告""开始抓取"按钮，对应位置改为"查看最近一次处理记录"与"在助手中继续"。
2. 工作台展示的所有结论性内容必须由助手写入并带版本号，工作台不自行拼接或推断。
3. 估值参数在工作台内可查看与调整，调整后保存为**参数草稿**，由助手执行重算并写回新版本；工作台不内置计算逻辑。
4. 处理失败时，工作台只呈现原因与定位信息（哪份文件、哪一页、哪项校验），重试在助手侧发起。
5. **报告定性章节（Part 6 优势 / Part 7 风险点）在新版本中不得自动沿用**，必须由用户在版本页逐条确认"仍成立 / 需改写 / 已失效"，否则该版本不可发布（第 6.6 节）。

### 2.5 状态机

**抽取批次**

| 当前状态 | 可流转到 | 触发 |
|---|---|---|
| 待获取（自动获取时） | 获取中 / 已取消 | 用户确认抓取范围 / 撤销 |
| 待解析 | 解析中 / 已取消 | 材料就位 |
| 解析中 | 待校验 / 解析失败（可部分失败） | 解析完成 |
| 待校验 | 待确认 / 校验不通过 | 勾稽校验完成 |
| 待确认 | 已入库 / 部分入库 | 用户完成确认 |
| 已入库 | （终态，可被后续快照引用） | — |
| 解析失败 / 校验不通过 | 重新解析 / 已取消 | 修复后重试 |

**指标值**

| 当前状态 | 可流转到 | 说明 |
|---|---|---|
| 机器提取 | 待确认 | 置信度中/低一律落到待确认 |
| 待确认 | 已确认 / 有争议 | 逐项或批量确认；争议项不参与估值、不进入快照的"估值可用"子集 |
| 已确认 | 已锁定 | 被已发布报告版本或已确认估值版本引用后自动锁定 |
| 已锁定 | 已确认（解锁） | 仅当引用它的版本全部归档/撤回，且用户显式操作 |
| 已确认 / 已锁定 | 已作废 | 出现更正版或重述，被新版本替代；旧值保留可查，不物理删除 |

**报告版本**

| 当前状态 | 可流转到 | 说明 |
|---|---|---|
| 草稿 | 待审阅 | 助手生成完成 |
| 待审阅 | 已发布 / 退回草稿 | 用户通过 / 要求重生成；定性章节未复核则禁止发布 |
| 已发布 | 已归档 | 出现更高版本时自动归档，仍可查看与对比 |
| 已归档 | —（只读） | 可"以该版为底稿"生成新版本 |

**估值版本**

| 当前状态 | 可流转到 | 说明 |
|---|---|---|
| 草稿 | 待确认 | 参数齐备、结果已算出 |
| 待确认 | 已确认 / 退回草稿 | 用户确认；缺必需数据或参数不合理则不可确认 |
| 已确认 | 待复核 | 上游数据快照变化、参数被改、市值过期 |
| 待复核 | 已确认（重算后为新版本） / 已归档 | 重算生成新版本，旧版本归档 |

## 3. 范围与优先级

### 3.1 P0：单企业完整闭环（含增量续更）

进入条件：用户指定一家企业并给出报告期区间（可投递文件，也可只给代码由助手下载）。

必须打通的路径：

1. 助手获取材料 → 识别报告期 → 回报"已识别 / 待指定 / 重复 / 不可用"；
2. 助手抽取指标（含分产品、分区域）→ 勾稽校验 → 工作台呈现待确认清单 → 用户确认 → 入库并生成**数据快照 S1**；
3. 助手基于 S1 生成深度分析报告 v1（7 部分骨架）→ 用户审阅 → 发布；
4. 基于 S1 做 DCF 测算 → 保存估值 v1（含敏感性）；
5. 追加新一期材料 → 新增报告期 → 快照 S2 → 报告 v2（基于 v1 全文演进）→ 估值标"待复核"→ 用户选择重算出估值 v2。

完成证据：企业详情页四个能力页签（概览 / 关键经营数据 / 深度分析报告 / 现金流估值）加"版本与来源"页均有内容；任一数字可点回来源文件的具体页；任一报告版本可还原"当时用了哪一版数据"。

恢复路径：抽错、校验不平、文件不含目标报告期、抓取失败时，用户能定位问题、修正或重跑，不需要重建企业。

> 本节动作除"确认/改值"外均由助手执行（见 2.4）。

### 5.1 指标分组（按样本重建）

### 5.2 材料接收与报告期识别（FR-D1 / FR-D2）

| 项 | 规则 |
|---|---|
| 执行方 | 助手侧：用户在会话中投递文件，或直接说明"用代码 600519 取 2016–2025 年报 + 全部季报" |
| 触发 | 明确的企业 + 报告期区间；区间上限默认 **10 年**（用户已批复固定） |
| 支持格式 | PDF（主）、Excel、Word、图片扫描件（标记需 OCR） |
| 企业指定 | 新建企业最小字段：名称、市场、代码（可空）、本位币、会计准则、报表口径（默认合并） |
| 疑似重复 | 名称高度相似（"某某科技" vs "某某科技股份有限公司"）先提示复用或新建，避免同一公司分裂 |
| 报告期识别 | 从标题与首页识别期间类型、财年、起止日期；含"摘要/（更正后）/英文版/日文版"时标"待人工指定"，不猜 |
| 处理反馈 | 助手逐份回报：已识别 / 未能识别 / 疑似重复 / 缺页；工作台"处理记录"留同一结果 |
| 禁止行为 | 不允许把不同企业的文件混入同一批次静默处理 |

### 5.3 抽取规则（FR-D3）

- 抽取范围由指标字典控制，不自由发挥；字典外的新科目先入"候选指标"待评审。
- 每个指标值必须记录：来源文件、页码/表名、**取的是哪一列（本期/上期/年初）**、原始单位、原始币种、是否合并报表、是否经审计、置信度。
- **扣非口径**：优先抽"扣除非经常性损益后的归属于母公司股东的净利润"；港股/美股无此科目时，抽"调整后净利润"并在 `caliber_note` 中注明换算方式 `[提案]`。
- 分产品/分区域数据：按年报"主营业务分行业、分产品、分地区情况"表抽取，必须同时抽"收入、成本"两项，毛利率由公式计算，不直接抄。
- 销量：仅对在年报中披露实物量的行业启用；无披露即"缺失"，不估算。
- 抽不到就是"缺失"，**不允许用 0 或估算值填充**；矩阵显示"待补"。
- 季度数据：**区分"累计值"与"单季值"**。年报/半年报/三季报披露的是累计值；单季值由差值计算，必须标记 `derived=是` 并展示计算式 `[提案]`。

### 5.4 校验与置信度（FR-D4）

校验清单见 12.3。不通过项不阻断入库，但计入"待确认"并在企业卡片显示红色计数；估值必需指标非"已确认"不得被估值引用。

| 级别 | 判定 | 处理 |
|---|---|---|
| 高 | 表格结构清晰、勾稽一致、摘要与正文数字一致 | 可批量确认 |
| 中 | 结构可解析但有单位/合并范围歧义，或仅单处出现 | 逐项确认 |
| 低 | 扫描件 OCR、跨页断表、数字缺失、多版本冲突 | 必须人工录入或核对后确认 |

### 5.5 人工确认与改值（FR-D5）

- 确认界面以"报告期 × 指标（× 维度）"列表呈现，支持"仅看异常""仅看估值必需"过滤。
- 单元格可展开：原文片段/截图、抽取值、历史值、校验提示、来源页。
- 三种动作：确认、改为人工值（留痕并注明原因）、标为争议（挂起，不参与估值）。
- 批量确认只对"高置信度且勾稽通过"生效。
- 确认人、确认时间、确认依据必须记录；任何修改产生新的指标值版本，旧值不删除。

### 5.6 入库、快照与展示（FR-D6）

- 入库后 `企业 + 报告期 + 指标 + 维度` 只有一个"当前有效版本"，历史版本在"版本与来源"可查。
- **一次确认完成即生成数据快照**（S1、S2…），快照记录：包含哪些报告期、哪些指标值版本、生成时间、确认人。
- 数据页默认展示：行 = 指标（按 G1–G7 分组，可展开维度），列 = 报告期（正序/倒序可切换），单元格 = 数值 + 单位 + 状态点。
- 视图切换：数值 / 同比 / 占比（占营收比）/ 图表；年份范围可切换（如仅显示近 5 年）。
- 每数字可点开来源与血缘。

### 5.7 异常与边界

| 情况 | 处理 |
|---|---|
| 文件不含财务三表（只有文字公告） | 批次标"不可用"，提示更换或补充 |
| 同期投递"报告 + 摘要 + 更正版" | 权威顺序：更正版 > 正式报告 > 摘要 > 英文版；其余作为附件保留并标注 |
| 单位不一致（元/千元/万元/百万元/千美元） | 统一换算为元存储，原文单位保留展示 |
| 币种不一致（HKD/USD/CNY/EUR） | 保留原币值；跨币种比较与估值按指定汇率换算，汇率来源与日期必须记录 |
| 分部口径改名（"智能家居"→"创新业务"） | 触发"维度映射待确认"，由用户决定是否归并；不自动合并 |
| 批次中途失败 | 已成功文件保留，失败文件可单独重试 |

## 7. M3 自由现金流（DCF）估值

**目的**：用**工作台内已经确认的数据**做可复用、可回溯的 DCF 测算，回答"以当前假设看，这个价格贵不贵"。

> 测算由助手执行；工作台提供参数面板、结果展示、敏感性表与适用性判断，不内置计算逻辑（2.4）。

### 7.1 口径选择（本次按样本改写默认值）

v1.1 默认 FCFF。样本三的做法是"经营现金流净额 − 资本支出"，折现率取自"机会成本"框架而非 WACC 推导。v2.0 因此把**口径 A 设为默认**，口径 B 保留。

| 口径 | 定义 | 折现率 | 结果 | 适用 |
|---|---|---|---|---|
| **A 股东现金流（默认）** `[样本事实]` | `FCF_t = 经营活动现金流量净额_t − 购建固定资产、无形资产和其他长期资产支付的现金_t`（差额为正即股东可分配现金） | 要求回报率 r，取**折现率配置项**（初始 10%，见 7.5.1） | `股权价值 = Σ FCF_t/(1+r)^t + TV/(1+r)^n + 货币资金 + 交易性金融资产 − 有息负债` | 现金流稳定、资本开支清晰的非金融企业 |
| B 企业现金流（可选） `[提案]` | `FCFF = EBIT×(1−t) + 折旧摊销 − 资本开支 − 营运资本增加` | WACC（可拆解展示 Rf、β、ERP、债务成本） | `股权价值 = 企业价值 − 净债务` | 资本结构变化大、需与同业 WACC 对齐时 |

共同规则：
- 显式预测期默认 **10 年**（样本为 Next1Y–Next10Y）`[样本事实]`；
- 增长率**分段**：第 1–5 年一档、第 6–10 年一档，末段向永续收敛；样本取 10% / 5% / 永续 3% `[样本事实]`；
- 终值统一用永续增长法 `TV = FCF_{n+1}/(r−g)`，不使用退出倍数（倍数法列为 P1 议题 Q-06）；
- 每条结果必须同时显示"企业价值 / 股权价值 / 每股价值 / 相对市值折溢价"四项，不允许只给一个数。

### 7.2 基准 FCF 的四种取法（样本已有，产品化为一等参数）

样本在企业池里同时维护 7 年均值、5 年均值、3 年均值、单年值四列 `[样本事实]`，说明"用哪一段做基准"对结论影响最大，必须显式让用户看到。

| 基准口径 | 计算 | 默认适用 |
|---|---|---|
| 最近一年 | 当年 FCF | 当年无异常且处稳态 |
| 近 3 年平均 | 3 年算术平均 | 有短期扰动 |
| **近 5 年平均（默认）** | 5 年算术平均 | 通用 `[提案]` |
| 近 7 年（或全部可得年度）平均 | 全区间平均 | 强周期企业 |

规则：
- 基准口径是**估值版本的一等字段**，切换即生成新的估值版本，不允许在同一版本内隐式改动；
- 页面必须并列展示四种基准下的股权价值，差异超过 30% 时提示"结论对基准口径高度敏感"；
- 计算基准所用的每一年 FCF 都要显示年份与值，并可点回数据页。

### 7.3 自由现金流稳定度与适用性

样本维护"自由现金流稳定程度"字段 `[样本事实]`。产品化为两个判定：

| 判定 | 计算 | 用途 |
|---|---|---|
| 稳定度 | `标准差(FCF_近5年) ÷ 均值(FCF_近5年)`（均值≤0 时改用以绝对值均值） | 决定是否展示"低估/高估"结论徽标 |
| 适用性 | 见 7.4 的硬性排除项 | 决定是否允许把 DCF 结果写入报告结论卡片 |

### 7.4 不适用与降级规则（由样本的失真反推）

样本中银行类企业股权价值出现 −45,022 亿元、部分企业货币资金与有息负债被填 0 `[样本事实]`，说明口径误用会直接产生荒谬结论。v2.0 强制以下规则：

| 情形 | 处理 |
|---|---|
| 金融业（银行/保险/证券/信托） | 默认**禁用**口径 A，页面提示"金融企业不适用自由现金流估值"；可手工输入替代估值（P1 议题） |
| 近 5 年 FCF 均值为负或波动度 > 1.0 | 结论徽标降级为"仅供参考"，并强制显示"FCF 波动过大" |
| 行业标签含"周期" | 结果旁固定显示"周期股：当前 FCF 可能处于周期高位/低位"，基准默认切为近 7 年 |
| 货币资金、有息负债任一缺失 | 禁止生成股权价值（只允许企业价值），并在页面标红"净现金项缺失" |
| 总股本缺失 | 允许股权价值，禁止每股价值 |
| 市值缺失或超过 90 天 | 允许计算，禁止显示"折溢价"，需先录市值时点 |

### 7.5 参数清单（每个参数都必须有来源与默认值）

| 参数 | 说明 | 来源 | 默认 | 约束 |
|---|---|---|---|---|
| 基准 FCF | 见 7.2 | 数据快照 | 近 5 年平均 | 必须来自已确认指标值 |
| g1（第 1–5 年） | 分段增长率 | 用户输入 / 历史 CAGR 建议值 | 10% `[样本事实]` | −20%–40% |
| g2（第 6–10 年） | 分段增长率 | 用户输入 | 5% `[样本事实]` | ≤ g1，≥ g |
| g（永续） | 永续增长率 | 用户输入 | 3% `[样本事实]` | 0%–5%，且 < r |
| r（折现率，口径 A） | 要求回报率，**配置项**（见 7.5.1） | 折现率配置（全局 / 行业档位 / 企业覆盖 / 本版手填） | 取配置当前值（初始 10%） | 6%–20%，且 > g |
| 显式期 n | 预测年数 | 固定 + 可调 | 10 年 | 5–15 年 |
| 货币资金 / 交易性金融资产 | 净现金加项 | 数据快照（最近报告期） | — | 缺失则禁用股权价值 |
| 有息负债 | 净现金减项 | 数据快照（短期借款 + 一年内到期非流动负债 + 长期借款 + 应付债券） | — | 同上 |
| 总股本 | 每股价值分母 | 数据快照 / 手工录入 | — | 缺失则禁用每股价值 |
| 市值 | 折溢价对照 | 手工录入（P0）/ 行情快照（P1） | — | 必须记录日期与来源 |

折现率取值必须给出"为什么是这个数"的一句话依据（沿用样本备注中的机会成本逻辑与同业参考：中石油 10%、昆汀科技 12.79%、苏州晟成 11.70%、高风险无形资产 16%–23%）`[样本事实]`，避免出现"拍一个数"。

### 7.5.1 折现率配置项（Q-02 已确认）

折现率**不做一次性基准取值**，而是作为可维护的配置项，按四层解析：

| 层级 | 内容 | 说明 |
|---|---|---|
| 全局默认 | `r_global`（初始 10%） | 所有企业的兜底值；沿用样本池备注的口径 `[样本事实]` |
| 行业档位 | 按行业标签配置一组 `r_industry` | 初始档位建议 `[提案]`：稳定消费/制造 10%、高成长或高不确定 12%–15%、强周期 11%、公用事业/类债 8%、金融不适用（口径 A 禁用） |
| 企业覆盖 | 单企业 `r_company` | 用于样本中出现的个案化取值（如 10%、12.79%、11.70%、16%–23% 的差异来源） |
| 本版手填 | 单次测算 `r_override` | 仅对当前估值版本生效，不写回配置 |

取值优先级：**本版手填 > 企业覆盖 > 行业档位 > 全局默认**。

配套规则：

1. 每个估值版本必须记录 `r`、**来源层级**、**配置版本号**，结果页显示"当前 r=10%（来源：行业档位·医疗器械，配置 v3）"；
2. 配置项自身带版本与留痕（谁改、旧值→新值、原因、生效时间），改动只影响**之后新建**的估值版本；
3. 已确认的估值版本按其快照可原样复算，配置变更不自动改数，仅在结果页提示"配置已更新，可重算"；
4. 敏感性矩阵的 r 轴以"配置值 ±4pct"自动生成区间，不写死 9%/10%；
5. 配置变更若使某企业结论方向反转，需在变更记录中提示受影响的已发布报告版本。

### 7.6 结果页呈现（对齐样本模板的列位）

| 区块 | 内容 |
|---|---|
| A 假设区 | 企业、基准报告期、口径（A/B）、基准 FCF 口径、g1/g2/g、r（含来源层级与配置版本）、n、净现金项、总股本、市值及时点 |
| B 预测表 | 行：Next1Y…Next10Y、永续；列：增长率、预测 FCF、折现因子、折现后 FCF（与样本"筛选后"模板一致） |
| C 结果区 | 企业价值、+ 货币资金/理财、− 有息负债、股权价值、每股价值、市值、折溢价、自由现金流稳定度 |
| D 敏感性区 | 5×5 矩阵：r × g（股权价值）；附 r × g1 与基准口径对比表 |
| E 判定区 | 适用性结论（正常 / 参考 / 不适用）、降级原因、结论徽标 |
| F 溯源区 | 引用的快照编号、每个输入指标值的 ID 与确认状态、生成时间 |

### 7.7 估值版本与复核触发

- 估值版本只增不改；同一企业同一快照下可并存多个"参数方案"（如乐观/中性/悲观），各自独立版本号；
- 以下任一发生时，已确认版本自动转"待复核"，**不自动重算、不自动改数**：
  1. 引用的数据快照有新版本；
  2. 任一输入指标值被改值或作废；
  3. 参数被编辑（保存草稿时提示"将产生新版本"）；
  4. 市值时点超过 90 天；
  5. 报告版本由用户要求"基于新估值重发"。
- 复核结论三选一：沿用旧值（记原因）、重算生成新版本、归档。

### 7.8 估值与报告的关系

- 报告不复制估值数字，只插入"估值版本卡片"（版本号 + 股权价值/每股价值 + 生成时间 + 参数摘要）；
- 估值出新版后，旧卡片标"已被 v(m+1) 取代"，报告正文不改；
- 报告发布时若引用的估值处于"待复核"，发布确认弹窗必须让用户显式选择"沿用旧估值引用"或"暂缓发布"。

### 7.9 企业池粗筛（P1-a，由样本反推的补充能力）

| 项 | 设计 |
|---|---|
| 目的 | 先用同一套简化口径全市场排序，再挑少数标的进入深研 |
| 数据 | 只维护：代码、名称、行业、近 N 年 CFO 与 Capex（用于算 FCF 均值）、股权价值、市值时点、高估程度、稳定度、周期标记 |
| 来源 | 助手批量抓取与测算后写入；工作台不自行计算 |
| 与企业的关系 | 池中一行**不是**企业；点"转入深研"才创建企业并进入首次投递流程 |
| 不做 | 池内不承载报告、不做精细估值、不展示分产品数据 |
| 风险提示 | 同一口径用于全市场必然产生失真（样本中银行、次新股已失真），池视图必须固定展示"口径局限"说明 |

## 8. 首次投递到工作台呈现：端到端流程

### 8.1 流程总览

```
用户：指定企业 + 报告期区间（投递文件 / 只给代码）
  │
  ├─ A 获取材料 ─────────── 助手抓取或接收；去重；权威版本判定
  ├─ B 识别与列清单 ─────── 识别报告期类型；确认企业；列出"已识别/缺失/待指定"
  ├─ C 抽取指标 ─────────── 按指标字典抽三表 + 分部 + 销量；记录来源与列位
  ├─ D 校验 ─────────────── 勾稽、跨年交叉、单位币种、置信度分级
  ├─ E 人工确认 ─────────── 工作台：确认/改值/标争议 → 入库
  ├─ F 生成数据快照 S1 ──── 冻结"本次有效指标值集合"
  ├─ G 生成报告 v1 ──────── 助手按 7 部分骨架撰写 → 草稿 → 审阅 → 发布
  └─ H 生成估值 v1 ──────── 参数确认 → 测算 → 敏感性 → 确认
        │
        └→ 工作台企业卡片转为"正常"，三块能力均有内容
```

### 8.2 分步说明

| 步骤 | 执行方 | 输入 | 动作 | 输出 | 检查点 |
|---|---|---|---|---|---|
| S1 指定 | 用户 | 企业名/代码、年份区间、市场 | 说明要哪些定期报告；可同时投递文件 | 处理请求 | 是否明确"年报 / 年报 + 半年报 + 季报"；区间是否 ≤ 10 年 |
| S2 建企 | 助手写、用户确认 | 名称、代码、市场、本位币、准则、报表口径 | 查重后创建企业 | 企业记录 | 是否与既有企业重复；代码与市场是否匹配 |
| S3 获取 | 助手 | 代码 + 期间 | 按第 13 章渠道抓取；或接收投递文件 | 来源文件清单 | 文件是否完整（非摘要/非英文稿）；同一期间是否有多个版本 |
| S4 识别 | 助手 | 文件 | 识别期间类型、财年、审计状态；标注不可用文件 | 报告期清单 | 是否有期间缺口（如缺 2019 年报）；是否有重复期间 |
| S5 抽取 | 助手 | 文件 + 指标字典 | 抽取三表与分部数据；记录页/表/列位/单位/币种 | 待确认指标值 | 抽取条数是否与指标字典要求匹配；是否有整表未命中 |
| S6 校验 | 助手算、工作台展示 | 指标值 | 执行 12.3 勾稽与置信度分级 | 校验结果与问题清单 | 勾稽不通过项是否可解释；跨年交叉校验是否一致 |
| S7 确认 | 用户（工作台唯一入口） | 待确认清单 | 确认 / 改值 / 标争议 | 已确认指标值 + 修改留痕 | 估值必需指标是否全部确认；争议项是否已说明 |
| S8 快照 | 助手写入 | 已确认集合 | 生成数据快照 S1 | 快照标签 | 快照内是否包含本次全部报告期；是否引用到争议项（不允许） |
| S9 报告 | 助手写、用户审阅 | 快照 S1 | 按 7 部分骨架生成 v1；标注数据引用 | 报告 v1 草稿 → 发布 | 每部分是否有结论句；引用数字是否全部可点开；定性章节是否自洽 |
| S10 估值 | 助手算、用户确认参数 | 快照 S1 + 参数 | 选择基准口径、填参数、测算、敏感性 | 估值 v1 | 适用性是否通过；净现金项是否齐备；折现率是否取自配置项并记录来源层级 |
| S11 收口 | 系统 | — | 企业卡片转"正常"；首页出现该企业 | 完整闭环 | 四个页签均有内容；任一数字可溯源 |

### 8.3 "首版完成"的判定标准（可验收）

| 编号 | 判定 | 证据 |
|---|---|---|
| V1 | 覆盖用户指定的全部报告期，缺口已列明 | 报告期清单与缺口说明 |
| V2 | G1/G2/G3/G4 核心指标完整度 ≥ 95%，缺失项全部为"年报未披露" | 完整度报表 |
| V3 | 勾稽校验通过率 ≥ 95%，未通过项均有解释 | 校验报告 |
| V4 | 估值必需指标 100% 处于"已确认"或"人工录入" | 确认状态统计 |
| V5 | 存在数据快照 S1，报告与估值均引用 S1 | 快照与版本记录 |
| V6 | 报告中每个数字可点到来源文件的具体页 | 抽查 10 处 |
| V7 | 估值结果页六区块齐全，敏感性矩阵可切换 | 页面检查 |

### 8.4 失败与恢复

| 失败点 | 表现 | 恢复方式 |
|---|---|---|
| 抓取失败（403/验证码/无数据） | 批次标"获取失败"，附渠道与时间 | 助手换渠道或请用户投递文件；工作台提供"跳过该期" |
| 文件不可用（扫描件、非目标期间） | 单文件标"不可用"并说明原因 | 替换文件或指定人工录入 |
| 抽取整表未命中 | 该报告期该组指标全为"待补" | 助手重试或人工录入；不得以估算填充 |
| 勾稽严重不符 | 版本可入库但整批标"待复核" | 定位差异科目后再确认 |
| 确认后才发现抽错 | 已入快照 | 走重述/更正流程（9.3 / 9.4）：改值产生新指标值版本 + 新快照，报告与估值进入待复核 |
| 报告生成失败 | 无草稿 | 助手重试；旧版本不受影响 |

## 9. 增量更新规则

### 9.1 五类变更（决定走哪条路径）

| 类型 | 定义 | 示例 | 路径 |
|---|---|---|---|
| U1 同企业新增一期 | 已覆盖企业出现新报告期 | 2025 年报、2026 一季报 | 9.2 |
| U2 新增企业 | 全新标的 | 加入一家港股公司 | 9.5 |
| U3 历史重述 | 旧期间数字被公司重述 | 2024 年报调整 2023 年数据 | 9.3 |
| U4 更正版 | 同一期间出现更正后报告 | "2024 年年度报告（更正后）" | 9.4 |
| U5 口径/字典变更 | 指标定义、分组、维度映射调整 | 新增"合同负债"、合并两个产品名 | 9.6 |

### 9.2 U1：同企业新增一期（核心路径）

| 步 | 动作 | 不覆盖原则 |
|---|---|---|
| 1 | 助手获取并识别新一期材料，写入新报告期 | 不触碰既有报告期 |
| 2 | 抽取 → 校验 → 用户确认 | 新指标值单独成版，既有值不动 |
| 3 | 生成新快照 S(n+1) | S(n) 保留且不可变 |
| 4 | 交叉校验：用新一期报告中的"上期/上年同期"列复核上一期值 | 若不一致 → 转 U3，不静默改 |
| 5 | 助手以"当前发布版报告"为底稿生成 v(n+1)，逐段标注变更类型 | 旧版本全文保留 |
| 6 | 定性章节（Part 6/7）进入"待复核"清单 | 不允许自动沿用 |
| 7 | 估值标"待复核"并列出触发原因与新可用数据 | 不自动改参数、不自动重算 |
| 8 | 用户决定：重算估值 / 沿用旧估值 / 归档 | 重算生成新版本，旧版本归档 |
| 9 | 企业卡片与首页更新"最新报告期 / 报告版本 / 估值状态" | — |
| 10 | 写入 `change_summary`：新增期、数字变化、结论变化、待复核项 | 作为评审依据 |

期间类型对三块能力的影响见 6.6；季度材料**不触发**年度指标重算与 DCF 重算。

### 9.3 U3：历史重述

- 触发：新一期报告的"上期比较数"与库内值不一致，或公司发布追溯调整说明。
- 处理：
  1. 生成"差异清单"（指标、期间、库内值、新材料值、差异率、可能原因）；
  2. 用户选择：接受重述（生成新指标值版本，旧值标"重述前"）/ 保留原值并记备注 / 标争议；
  3. 接受重述后生成新快照，并标记"哪些年度的衍生指标（CAGR、周转天数）需重算"；
  4. 报告新增"口径变更说明"段落，受影响年份段落标注"重述后口径"，脚注保留原值；
  5. 引用受影响期间的估值版本转"待复核"。
- 禁止：直接覆盖旧值、在报告中无声替换数字。

### 9.4 U4：更正版

- 权威顺序：更正版 > 正式报告 > 摘要 > 英文版；更正版入库后旧文件标"已被替代"，**文件与抽取结果都保留**。
- 差异处理同 U3；若更正版仅修正文字不影响数字，则只更新文件版本与备注，不产生新指标值版本。
- 同一期间同时存在两份有效文件时，页面必须显示"当前采用哪份、为什么"。

### 9.5 U2：新增企业

- 与既有企业完全隔离，独立报告期、独立快照、独立报告与估值。
- 复用内容：指标字典、报告骨架、估值参数模板、行业标签。
- 不复用：任何其他企业的指标值、结论、估值参数（不得把 A 企业参数默认带入 B 企业）。
- 行业标签决定：G6 实物量是否启用、周期标记、金融业禁用法。
- 同名/近名查重（5.2）。

### 9.6 U5：口径与字典变更

| 变更 | 影响 | 处理 |
|---|---|---|
| 新增指标 | 历史期缺失 | 生成"回填任务"，可只回填最近 3 年；未回填的年份显示"未采集"而非 0 |
| 指标定义修改（如应收款是否含票据） | 全历史不可比 | 必须新建指标条目（新 ID），旧指标标"已弃用"，报告注明切换点 |
| 维度映射调整 | 分部序列断裂 | 在维度映射表新增映射关系，历史数据保留原名，展示层按映射归并并标注 |
| 报告骨架调整 | 新旧版本结构不同 | 旧报告只读；新版本按新骨架生成，对比视图按"部分"对齐 |

### 9.7 幂等与去重

- 同一文件（内容哈希相同）重复投递：不重复建报告期，提示"已存在，是否重跑抽取"。
- 同一期间不同来源（交易所 vs 公司官网）：以交易所/官方披露为准，另一份作附件。
- 同一批次内同一期间出现两次：拒绝并提示指定权威版本。

### 9.8 影响面矩阵

| 变更 | 指标值 | 数据快照 | 报告 | 估值 | 企业池 |
|---|---|---|---|---|---|
| U1 新增年报 | 新增 | 新建 | 新版本（段落级演进） | 待复核 | 相关行更新 |
| U1 新增半年报/季报 | 新增 | 新建 | 新版本（仅季度小节） | 标记"最新进展"，不重算 | 不变 |
| U2 新增企业 | 全新 | 新建 | 首版 | 首版 | 可能由池转入 |
| U3 重述 | 旧值作废 + 新版本 | 新建 | 新版本 + 口径说明 | 待复核 | 相关行更新 |
| U4 更正版 | 视差异 | 视差异 | 视差异 | 视差异 | 视差异 |
| U5 字典变更 | 可能回填 | 新建 | 注明切换点 | 参数/定义提示 | 建议重算 |

## 10. 版本与确认状态规则

### 10.1 四类版本

| 版本 | 命名 | 粒度 | 只增不改 | 必须记录 |
|---|---|---|---|---|
| 指标值版本 | `MV-{企业}-{期间}-{指标}-{维度}-v{n}` | 单个值 | 是 | 来源、抽取器版本、确认人、改值原因 |
| 数据快照 | `S{n}` | 企业级集合 | 是 | 包含的指标值版本清单、报告期集合、生成时间 |
| 报告版本 | `R{n}` | 全篇 | 是 | 基于的快照、覆盖期间、变更摘要、定性复核记录 |
| 估值版本 | `V{n}`（可带方案后缀，如 `V2-保守`） | 一次测算 | 是 | 快照、基准口径、全部参数、输入值 ID、市值时点 |

### 10.2 对象关系（基数与约束）

| 关系 | 基数 | 约束 |
|---|---|---|
| 企业 → 报告期 | 1 : N | 报告期唯一键 = 企业 + 类型 + 财年 + 期间序号 |
| 报告期 → 指标值 | 1 : N | 同一(指标, 维度) 只有一个"当前有效"版本 |
| 企业 → 数据快照 | 1 : N | 快照一经生成不可编辑，只能新建 |
| 数据快照 → 指标值版本 | N : N | 快照保存"值版本 ID 列表"，因此可完整还原当时数据 |
| 企业 → 报告 | 1 : N（通常 1） | 报告版本 N 必须且只能引用一个快照 |
| 企业 → 估值模型 | 1 : N（按口径/方案） | 估值版本 N 必须引用一个快照 + 一组参数 |
| 报告版本 → 估值版本 | N : M（通过引用卡片） | 引用关系记录被引用的估值版本号 |
| 企业池行 → 企业 | 0..1 : 1 | 转入后建立关联，池行保留为来源线索 |

### 10.3 版本之间的三种"不一致"及处置

| 不一致 | 含义 | 处置 |
|---|---|---|
| 报告引用的快照不是最新 | 报告落后于数据 | 顶部提示"有新数据，建议出新版"，不自动改 |
| 估值引用的快照不是最新 | 估值落后于数据 | 估值转"待复核" |
| 报告中引用的指标值与当前值不同 | 发布后改值 | 提示"引用数据已更新"，人工决定是否出新版 |

### 10.4 确认矩阵（谁确认什么、确认后锁定什么）

| 对象 | 确认人 | 确认动作 | 确认后效果 | 可否撤销 |
|---|---|---|---|---|
| 指标值 | 用户 | 确认 / 改值 | 该值可被快照引用；被发布版本引用后自动"已锁定" | 可解锁（需先撤回引用版本） |
| 数据快照 | 系统（确认完成即生成） | — | 冻结引用集合 | 不可撤销，只能新建 |
| 报告草稿 | 用户 | 发布 | 版本只读，引用指标值锁定 | 仅可归档，不可删 |
| 报告定性章节 | 用户 | 逐条"仍成立/需改写/已失效" | 允许发布 | 发布前可改 |
| 估值参数 | 用户 | 确认参数 | 参数随版本冻结 | 编辑即产生新版本 |
| 估值结果 | 用户 | 确认 | 可用于报告引用；输入值锁定 | 上游变化即转待复核 |
| 企业基础信息 | 用户 | 保存 | 影响口径（币种、准则） | 可改，但需重算提示 |

### 10.5 上游变化 → 下游联动（唯一规则表）

| 上游事件 | 指标值 | 快照 | 报告 | 估值 |
|---|---|---|---|---|
| 新增报告期并确认 | 新增 | 新建 | 提示出新版 | 待复核 |
| 改值（已确认值） | 新版本，旧版作废 | 新建 | 提示出新版 + 引用失效提示 | 待复核 |
| 标争议 | 状态变更 | 新建（不含该值） | 引用该值的段落标"数据待定" | 不可引用该值 |
| 新增维度/分部 | 新增 | 新建 | 分部段落提示更新 | 一般不影响 |
| 参数编辑 | — | — | 提示 | 新版本 |
| 市值过期 | — | — | — | 仅隐藏折溢价 |

### 10.6 时间线示例（同企业续更）

| 时间 | 事件 | 数据 | 报告 | 估值 |
|---|---|---|---|---|
| T1 | 首次建企（2016–2024 年报） | S1 | R1 发布 | V1 确认 |
| T2 | 追加 2025 半年报 | S2 | R2（仅季度小节变更） | V1 保持，标"最新进展" |
| T3 | 追加 2025 三季报 | S3 | R3 | 同上 |
| T4 | 追加 2025 年报 | S4 | R4（Part 2/5 刷新 + Part 6/7 复核） | V1 → 待复核 → V2 确认 |
| T5 | 发现 2023 年应收款抽错，改值 | S5 | 提示 R5 | V2 待复核 |

### 11.3 报告与估值的锚点

- **报告锚点**：每个 Section 保存 `cited_value_ids[]`；报告页任一数字可反查其指标值，再由指标值查到文件页。
- **估值锚点**：估值版本保存 `input_snapshot`（每个输入指标的值 ID + 版本 + 值）与 `param_snapshot`（全部参数）。因此任意历史估值都能完整复算。
- **反向查询**：指标值详情页显示"被 R3、R4 引用；被 V1、V2 使用"。

### 11.4 用户可见的血缘呈现

| 场景 | 呈现 |
|---|---|
| 数据页单元格 | 悬浮显示"来源：2024 年报 P.86｜置信度：高｜已确认（张三，2026-05-12）" |

### 11.5 保留策略

- 来源文件、抽取记录、指标值历史版本、报告历史版本、估值历史版本**永久保留**；
- 财务报表类内容仅在内部使用，不提供对外分发与导出原文（3.3）；
- 任何"删除企业"的操作实为归档，血缘链保留。

## 12. 数据质量与口径规则

### 12.1 单位与币种

- 存储统一"元"（本位币），展示默认"亿元"（与样本一致 `[样本事实]`），保留 1–2 位小数，可切换"元/万元/亿元"；
- 比率统一存小数（0.4412），展示为百分比（44.12%），禁止存"44.12%"字符串；
- 负数一律保留负号，不用括号代替；
- 币种：保留原币值与币种代码；换算需记录汇率、汇率日期与来源；同表内不同币种必须显著标注（样本二混排欧元、美元企业）。

### 12.2 报表口径

- 默认合并报表；母公司报表仅在用户显式要求时采集，并作为独立维度；
- 同一企业在不同期间的口径变化（如首次执行新收入准则）必须在"口径变更"中登记，报告在切换年度注明。

### 12.3 勾稽校验清单（不通过即降级为待确认）

| 编号 | 校验 | 容差 |
|---|---|---|
| K1 | 流动资产 + 非流动资产 = 资产总计 | 0 |
| K2 | 流动负债 + 非流动负债 = 负债合计 | 0 |
| K3 | 负债合计 + 所有者权益 = 资产总计 | 0（允许四舍五入 1 个单位） |
| K4 | 归母净利润 + 少数股东损益 = 净利润 | ≤ 0.5% |
| K5 | 经营 + 投资 + 筹资净额 ± 汇率影响 = 现金净增加额 | ≤ 0.5% |
| K6 | 期初现金 + 净增加额 = 期末现金 | 0 |
| K7 | 分产品收入合计 ≈ 营业收入 | ≤ 2%（允许"其他业务"差额） |
| K8 | 分区域收入合计 ≈ 营业收入 | ≤ 2% |
| K9 | 分部毛利合计 ≈ 营业收入 − 营业成本 | ≤ 2% |
| K10 | 毛利率 = (营业收入 − 营业成本) ÷ 营业收入 | 与披露值差 ≤ 0.2pct |
| K11 | 资产负债率 = 负债合计 ÷ 资产总计 | ≤ 0.2pct |
| K12 | 应收账款周转天数 = 平均应收 ÷ 营业收入 × 365 | 与披露/样本差 ≤ 5% |
| K13 | **跨年交叉校验**：新一期报告"上期数"与库内上一期值一致 | 0（不一致 → U3） |
| K14 | 摘要与正文同名指标一致 | 0 |
| K15 | 扣非净利润 ≤ 净利润（出现反向必须解释） | 语义校验 |
| K16 | 自由现金流 = 经营净现金流 − 资本开支 | 0 |

K13 是从样本一的"应收款及较前一年增加额"表得到的启发：**下一年年报的上期列是最便宜的独立校验源**，应作为默认动作。

### 12.4 跨准则口径映射（港股/美股）

| A 股口径 | 港/美映射 | 说明 |
|---|---|---|
| 扣非净利润 | 调整后净利润（Adjusted Net Income）/ 持续经营净利润 | 无统一科目，须在 `caliber_note` 注明选择依据 `[提案]` |
| 经营净现金流 | Net Cash from Operating Activities | 一致 |
| 资本开支 | Purchases of PP&E（含无形资产时须注明） | 是否含无形资产购置会影响 FCF，必须统一并在页面提示 |
| 有息负债 | Short-term borrowings + Current portion of LTD + LTD + Bonds | 租赁负债是否计入需固定规则 `[TBD]` |
| 营业收入 | Revenue / Total Revenue | 注意"Total revenue vs Operating revenue"差异 |

### 12.5 缺失值规则

- 缺失即"待补"，永不填 0、永不估算、永不沿用相邻年份；
- 报告写作时遇到缺失，写"未披露"或跳过该结论，不写"约"；
- 估值遇到缺失：必需项缺失则禁用对应结果（7.4），非必需项按 0 处理但必须在结果页标注"该项按 0 处理"。

### 12.6 争议与改值留痕

- 争议项在矩阵中以黄色标记，在报告中标"数据待定"；
- 改值必须填写原因（下拉：抽取错误/单位错误/口径错误/重述/其他）；
- 改值记录进入版本与来源时间轴，任何人可看到"谁在何时把 A 改成 B，为什么"。

### 12.7 完整度评分（企业卡片展示）

`完整度 = 已确认的"估值必需指标"数 ÷ 应有数`，仅统计最近一期与近 5 年；低于 80% 时企业卡片显示橙色，且禁止发布引用该数据的新报告版本（可在弹窗中强制覆盖并记录原因）。

## 13. 材料自动获取：渠道、限速、合规与人工校验

前提：**工作台不做抓取**（2.4）。用户只说"要哪家企业、哪几年的哪些定期报告"，由助手执行获取；工作台只记录获取结果与来源，供审计。

### 13.1 渠道与优先级

| 市场 | 主渠道 | 备渠道 | 覆盖材料 | 说明 |
|---|---|---|---|---|
| A 股 | 巨潮资讯网公告检索（按公告类别筛"年度报告 / 半年度报告 / 季度报告"） | 上交所、深交所官网 | 年报、半年报、一季报、三季报、更正版、摘要 | A 股首选；更正版与摘要需一并识别 |
| 港股 | 披露易（HKEXnews）标题检索 | 公司投资者关系页 | 年报、中报、季报（部分公司自愿披露）、公告 | 仅内部使用；默认**不开启**，需用户显式授权 |
| 美股 | SEC EDGAR（提交清单接口 + 结构化财务数据接口） | 公司 IR 页面 | 10-K、10-Q、20-F、6-K、8-K | 优先取结构化数据（XBRL），再回落到 PDF；外国私人发行人常为 20-F 年报 + 6-K，无完整季报 |
| 非上市 | 无公开渠道 | 用户投递 | 审计报告、内部报表 | 只能投递，不抓取 |

抓取范围：默认"年报 N 年"，可加"半年报 + 季报"；回溯上限 **10 年**（用户已批复）。

### 13.2 限速、重试与礼貌抓取

| 项 | 规则 |
|---|---|
| 单域并发 | 1（同一站点串行请求） |
| 请求间隔 | 巨潮 / 交易所 ≥ 1.5 秒；披露易 ≥ 2 秒；SEC ≥ 0.2 秒（并遵守其 10 次/秒上限） |
| 退避 | 403 / 429 / 5xx：指数退避（2s→4s→8s），最多 3 次；仍失败则切备渠道 |
| 单批次上限 | 单企业单次不超过 40 份文件；超过需拆分并告知用户 |
| 请求标识 | 使用可识别的 User-Agent 与联系邮箱（SEC 明确要求），不伪装浏览器批量抓取 |
| 时段 | 不在交易所公告高峰（工作日 16:00–20:00）批量抓取 |
| 缓存 | 下载文件按内容哈希去重，同一文件不重复下载 |
| 记录 | 每次请求记录：渠道、URL、时间、状态码、重试次数、耗时 |

### 13.3 合规红线

1. 只访问公开披露页面，**不绕过验证码、不破解登录、不使用付费数据库**（用户已明确不采购）；
2. 不抓取、不存储与投资分析无关的个人信息；
3. 港股材料**仅限内部研究使用**，不对外分发、不二次发布、不进入报告附件对外提供（用户已确认）；
4. 不把整份原文 PDF 再分发；报告中引用原文仅限必要片段，并标注来源；
5. 遵守站点 robots 与使用条款；出现明确禁止抓取的提示即停止该渠道并记录；
6. 抓取失败不构成"用估算补齐数据"的理由。

### 13.4 人工校验（必须存在，且分三层）

| 层 | 环节 | 规则 |
|---|---|---|
| L1 机器校验 | 勾稽 + 跨年交叉 + 摘要/正文一致性（12.3） | 全量执行，不通过即降级 |
| L2 人工全检 | **估值必需指标**（基准 FCF 相关、净现金项、总股本、营业收入） | 必须逐项确认，才可进入估值 |
| L3 人工抽检 | 新建企业首次投递 | 随机抽取 **≥ 20%** 指标值（不少于 20 项）对照原文核对 |
| L3' 抽检降级 | 同一企业连续 2 期抽检零差错 | 抽检比例可降至 10%，但估值必需指标仍全检 |
| L3'' 抽检升级 | 出现 1 处实质错误 | 该企业下一期恢复 20% 抽检，并回溯最近 2 期 |

抽检结果必须记录（抽检人、样本量、错误数、错误类型），用于评估抽取质量；抽取器或模板升级后，抽检比例临时恢复 20%。

### 13.5 抓取与投递的关系

| 情形 | 处理 |
|---|---|
| 用户只给"企业 + 年份" | 助手按 13.1 抓取，回报获取清单与失败项 |
| 用户直接投递文件 | 以投递文件为准；若与抓取件冲突，按 9.4 权威顺序处理 |
| 抓取件为扫描版（无文本层） | 标记"需 OCR"，OCR 结果置信度一律按"低"，必须人工核对 |
| 港股未获授权 | 提示"该市场默认不自动获取，请投递文件或显式授权" |
| 美股只有 20-F（无季报） | 报告期清单中注明"该市场无强制季报"，不视为缺口 |

### 13.6 获取失败的降级路径

`主渠道失败 → 备渠道 → 用户投递 → 人工录入关键指标（仅估值必需项）`。任一环节降级都要在批次记录中留痕，并在企业卡片显示"该期数据来源为人工录入"。

## 17. 与上一版 PRD（v1.1）的差异说明

### 17.1 沿用（不做改动）

| 项 | 说明 |
|---|---|
| 产品定位 | "承载解析结果的价值投资研究工作台"，不做实时行情、不做买卖建议 |
| 处理位置约定 | 工作台无模型能力；解析、抽取、写作、测算全部在助手侧，工作台只承载与确认（2.4 保留并加第 5 条） |
| 一级对象 | 企业 → 报告期 → 指标值 → 报告 / 估值的主干关系不变 |
| 指标值状态机主干 | 机器提取 → 待确认 → 已确认 → 已锁定，增加"已作废"分支（因重述需要） |
| 报告只增不改 | 版本不覆盖、发布后只读 |
| 估值只增不改 | 参数与结果随版本冻结 |
| 数据血缘要求 | 指标值必须可追到文件与页码（本次细化到"列"与"派生公式"） |
| 自动获取的合规底线 | 只用公开渠道、限速、不绕过验证码（本次补充港股授权与 SEC 标识要求） |
| 非目标清单 | 实时行情、买卖建议、组合回测、对外分发 |
| 指标字典的"受控"原则 | 抽取范围由字典控制，不自由发挥 |

### 17.2 修订（改了，并说明为什么）

| 编号 | 章节 | v1.1 | v2.0 | 为什么改 |
|---|---|---|---|---|
| R1 | 报告骨架 | 8 章（含独立摘要章、独立估值章） | **7 部分**（Part 1–7，摘要变结论卡片，估值变引用卡片） | 三份样本的实际骨架是 7 部分且无估值章；摘要与估值独立成章会与 Part 1、估值页重复维护 |
| R2 | 报告写作口径 | 以净利润/归母净利润为主 | **以扣非净利润、扣非 ROE、扣非净利率为主口径** | 样本一、样本二均以扣非为核心指标 |
| R3 | DCF 默认口径 | FCFF（EBIT 口径） | **股东现金流（经营净现金流 − 资本开支）为默认**，FCFF 可选 | 样本三 5,462 行企业池与单企业模板均用该口径；保持与用户既有结果可比 |
| R4 | DCF 参数 | 未明确基准 FCF 取法 | 新增**基准 FCF 四口径选择器**（1/3/5/7 年）为一等参数 | 样本同时维护四种口径，说明这是结论的最大变量 |
| R5 | DCF 结果项 | 企业价值、股权价值 | 增加**每股价值、相对市值折溢价、自由现金流稳定度、适用性判定** | 样本企业池已有稳定度与高估程度字段；缺适用性判定会产生 −45,022 亿元的荒谬值 |
| R6 | 指标分组 | 4 组（利润表/资产负债表/现金流量表/衍生） | **7 组**（G1–G7），新增分部数据、实物量，并拆出"主要经营指标" | 样本二的实际结构是"主要指标 / 增幅 / 成本结构 / 产品 / 区域 / 销量 / 资产负债简表" |
| R7 | 指标维度 | 无维度概念 | 指标值支持**产品 / 区域 / 渠道维度** | 没有维度就无法承载样本的分产品、分区域数据 |
| R8 | 报告增量更新 | "未受影响章节原文保留" | **定性章节（Part 6/7）禁止静默沿用，必须逐条复核** | 数据变了而结论没变是最大风险；"保留"与"确认过"必须可区分 |
| R9 | 版本关系 | 只说"报告基于某版数据" | 引入**数据快照 S{n}** 作为唯一版本引用锚点 | 否则无法回答"R3 用的是哪一版指标值"，也无法复算历史估值 |
| R10 | 估值与报告 | 报告中复述估值数字 | **报告只引用估值版本卡片，不复制数字** | 避免两处数字不一致，避免估值更新后报告变成假信息 |
| R11 | 参考样本使用 | 因环境限制未解析，结论标注为推测 | **三份样本已实际解析**，报告骨架、指标分组、估值口径均据实校准；剩余推测项列于 0.3 | 本次环境可用（Python 3.12.8） |
| R12 | 自动获取 | 渠道与限速为待定项 | 渠道、限速、退避、合规红线、三层人工校验**落为规则**，并按用户批复固定"10 年上限、不采购、港股仅内部、需要季报" | 用户已批复，待定项可以关闭 |
| R13 | 季度数据 | 未区分累计值与单季值 | 强制区分，单季值标记 derived 并显示计算式 | 样本一的"各季度经营现金流"表要求单季口径，否则季节性判断失真 |
| R14 | 缺失值 | 允许"按 0 处理" | **必需项缺失即禁用对应结果**；非必需项按 0 必须标注 | 样本中净现金项被填 0 直接扭曲结论 |
